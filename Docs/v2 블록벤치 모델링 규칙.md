## 1. 기본

- 프로젝트 형식은 **Generic Model**(일반 모델)이다.
- 크기는 **1유닛 = 16픽셀**이다. 큐브 맵의 블록 한 칸(1 × 1 × 1)이 Blockbench에서 **16 × 16 × 16**이다. 모든 모델이 같은 크기를 쓴다.
- 큐브의 위치·크기는 **정수 픽셀**로 둔다(격자 맞춤 1). 반 픽셀은 쓰지 않는다.
- 텍스처는 **1픽셀 = 모델 1픽셀**(16 × 16 텍스처 픽셀 = 블록 한 면) 밀도로 칠한다. 가져오기는 픽셀 그대로 보이게(Point 필터) 한다.
- 모델은 **`.bbmodel` 그대로** `Assets`에 저장한다(glTF·OBJ로 내보내지 않음). 텍스처는 **파일 안에 넣어**(embedded) 저장한다. 파일 하나가 **프리팹 하나의 겉모습**이다.
- UV는 면마다 UV(per-face)와 Box UV 둘 다 된다. 가져오기는 면마다 적힌 UV를 읽는다.

## 2. 그룹: 부품과 부위 태그

그룹 이름이 두 가지 역할을 한다.

- **부위 태그 그룹**: 이름이 부위 태그(3절: `Gray`·`Color`·`Glass`·`GrayGlass`·`Light`)인 그룹. 그 안의 큐브가 그 부위가 된다. 큐브는 자기를 감싼 그룹 중 **가장 가까운 태그 그룹**을 따른다.
- **부품 그룹**: 태그가 아닌 이름의 그룹. Unity에서 **자식 오브젝트 하나**가 되고 그룹 이름을 그대로 쓴다. 자식의 원점은 그룹의 **기준점(origin)**이다. 움직이는 부품(차단기 막대 등)은 반드시 부품 그룹으로 나누고 이름을 붙인다.
- 부품 그룹 안에 태그 그룹을 넣는다. 예(차단기):

```
BoomGate            (부품: 맨 위)
├─ Base             (부품: 받침)
│  ├─ gray          (받침의 흑백 부분)
│  ├─ Color         (받침의 칠하는 띠)
│  └─ Glass         (받침의 반투명 창)
└─ Stick            (부품: 움직이는 막대, 기준점 = 회전축)
   ├─ color         (막대의 칠하는 부분)
   └─ light         (막대 끝 불빛)
```

- 이름은 **대소문자를 구분하지 않는다**(`gray` = `Gray`). 태그 이름은 부품 이름으로 쓰지 않는다.
- 어느 태그 그룹에도 속하지 않은 큐브는 `Gray`로 본다.

## 3. 부위 (태그)

Blockbench에서는 **컬러로 모델링**한다. Unity는 칠한 픽셀의 **휘도 Y**(YCbCr의 Y, 정확한 흑백값)만 쓴다.

- **휘도 Y** = 0.299 R + 0.587 G + 0.114 B (ITU-R BT.601, sRGB 0~1 값 그대로). 흰색 1, 검정 0.
- **Unity 색**: 모델마다 하나. 놓인 모델마다 인스펙터에서 정하고, 기물(요구 색·색 원천)과 캐릭터(지금 색) 코드가 실행 중에 바꾼다. Color·Glass·Light가 같은 색을 쓴다.
- **불투명도**(Glass·GrayGlass): Unity에서 **프리팹마다** 하나로 정한다(Light의 발광 세기처럼). 한 프리팹의 모든 반투명 부위가 같은 불투명도다.

| 태그 | 색 | 불투명도 | 발광 | 쓰임 |
|---|---|---|---|---|
| **Gray** | 흑백: Y | 불투명 | 없음 | 무채색 월드의 대부분(블록, 기물 몸체) |
| **Color** | Unity 색 × Y | 불투명 | 없음 | 값에 따라 색이 바뀌는 부분 |
| **Glass** | Unity 색 × Y | 프리팹의 불투명도 | 없음 | 색이 있는 반투명 부분(므엥 몸 등) |
| **GrayGlass** | 흑백: Y | 프리팹의 불투명도 | 없음 | 색이 없는 반투명 부분 |
| **Light** | Unity 색 × Y | 불투명 | Unity 색 × Y × 발광 세기 | 빛나는 부분 |

- Gray 그룹에 색을 칠해 두어도 Unity에서는 흑백이다. Blockbench 화면과 Unity 화면이 다르게 보이는 것은 정상이다.
- Color·Glass·Light는 Blockbench에서 칠한 **색조는 쓰지 않고 휘도만** 쓴다. 미리 보기 편하게 아무 색으로 칠해도 된다.
- **반투명**(Glass·GrayGlass)은 바깥 껍질만 만들고(반투명 큐브끼리 맞닿아 완전히 덮인 면은 버림) 양면으로 그린다(뒷면 먼저, 앞면 나중). 유리 상자처럼 반대편 벽과, 안에 든 불투명 큐브가 비쳐 보인다.
- **발광 세기**와 **불투명도**는 Unity에서 **프리팹마다** 정한다. 값은 프리팹마다의 겉모습 프리셋(`Assets/Data/Looks`, 재질감과 함께)에 있고, 메뉴 Slime~ColorMaker~/프리팹 설정이나 프리팹 맨 위 인스펙터의 '모델 겉모습' 칸에서 고친다. Light가 있는 부품에는 가져오기 코드가 **광원**(포인트 라이트, 실시간)을 Light 부분 가운데에 하나 만들어 주변도 비춘다(색 = Unity 색, 세기 = 발광 세기 × 광원 세기 배율, 범위·그림자도 겉모습 프리셋에서).
- **부위는 나중에 더할 수 있다**: 가져오기 코드의 부위 표에 한 줄을 더하고 이 표에 적는다.
- 재질감(광택·메탈릭 등, `SurfaceFinish`)은 부위마다 따로 고른다.

## 4. 폴더와 이름

- 저장 위치는 **기존 `.vox` 모델과 같은 폴더**를 그대로 쓴다(`Assets/Models/` 아래, 하위 폴더는 `Assets/Prefabs/`와 같음). 예: `Models/CubeGrid/Block.bbmodel`, `Models/Fixtures/BoomGate/BoomGate.bbmodel`, `Models/Meueng/Meueng.bbmodel`. 시험 파일은 `Models/Tests/`.
- 파일 이름은 그 모델을 쓸 **프리팹 이름**과 같다(영어 PascalCase).

## 5. 축, 앞면, 기준점

### 축

Blockbench 화면 바닥의 방위 표시(N·E·S·W)를 기준으로 한다.

| Blockbench | Unity |
|---|---|
| 위 (+Y) | 위 (+Y) |
| 동쪽 E (+X) | 오른쪽 (+X) |
| 북쪽 N (−Z) | **앞 (+Z, `transform.forward`)** |
| 남쪽 S (+Z) | 뒤 (−Z) |

- 다시 말해 **Unity에서 모델 뒤에 서서 앞을 보는 모습 = Blockbench에서 남쪽에 서서 북쪽을 보는 모습**이다. 왼쪽·오른쪽, 위·아래가 그대로 맞고 모양이 거울처럼 뒤집히지 않는다.
- 왜 Z만 바꾸나: Blockbench는 오른손 좌표(Z가 화면 앞으로 나옴), Unity는 왼손 좌표(Z가 화면 안으로 들어감)라 좌표를 그대로 옮기면 모델이 거울상이 된다. Z 하나의 부호를 바꾸면 모양이 그대로 옮겨지고, 그 결과 북쪽이 Unity 앞이 된다. 가져오기는 Blockbench (X, Y, Z)를 Unity (X, Y, −Z)로 바꾼다.
- **앞면**(정면)은 북쪽 면이다. 기물의 얼굴, 캐릭터의 눈, 계단이 오르는 쪽을 북쪽으로 둔다.
- 회전값도 같은 규칙으로 바뀐다(가져오기가 처리): X축·Y축 회전은 부호가 바뀌고, Z축 회전은 그대로다. Blockbench에서 보이는 모습 그대로 Unity에 나오므로 모델링할 때 신경 쓸 필요는 없다.

### 기준점

- 파일 안 **모든 큐브를 합친 상자**로 정한다(Blockbench 원점에 맞춰 둘 필요 없음). 가져오기 설정(파일마다 인스펙터)에서 고른다.
  - **바닥면 가운데 (기본값)**: 블록, 계단, 칸 바닥에 서는 기물.
  - **바닥면 뒤쪽 가운데**: 블록 옆면에 붙는 기물(뒤 = 남쪽 면).
  - **윗면 가운데**: 윗면을 기준으로 하는 것.
  - **Blockbench 원점 그대로**: Blockbench의 원점(0, 0, 0)이 Unity 모델의 원점이 된다. 7절에서 변환한 모델은 모두 이 설정이다(옛 `.vox`와 같은 자리, 블록·계단은 원점 = 바닥면 가운데).

### 그 밖

- **회전**: 큐브 회전은 쓸 수 있다. 다만 회전한 큐브는 지형의 맞닿은 면 숨기기와 상자 콜라이더에서 빠진다(축에 맞는 큐브만 판단).
- **쓰지 않는 것**(처음 범위): Blockbench 애니메이션, 메시(Mesh) 도구로 만든 요소, 로케이터·널 오브젝트. 숨긴(내보내기 끔) 큐브는 가져오지 않는다.

## 6. 블록과 계단

큐브 격자의 지형이다. 모델을 칸 하나(16 × 16 × 16)에 맞추고 기준점은 '바닥면 가운데'다(변환한 블록·계단은 원점을 칸 바닥 가운데에 두고 '원점 그대로').
프리팹은 모델을 칸 가운데에서 0.5유닛 아래(칸 바닥)에 둔다.

| 모델 | 크기 (픽셀) | 메모 |
|---|---|---|
| 블록 (`CubeGrid/Block`) | 16 × 16 × 16 | 한 칸을 채운다. |
| 계단 (`CubeGrid/Stair`) | 16 × 16 × 16 | 그 칸 안에서 한 칸 높이를 북쪽으로 오른다. |

- **충돌은 모델 모양 그대로**다. 가져오기 설정의 '상자 콜라이더'를 켜면 축에 맞는 큐브마다 상자 콜라이더(자식 `Collider (n)`)를 만든다(경사 콜라이더 없음). 지금 계단만 켰다(블록은 프리팹의 한 칸 상자, 기둥은 모델 메시 콜라이더). 계단의 한 단 높이는 캐릭터가 넘는 턱(`PlayerMoveSettings`, 지금 0.3유닛 = 4.8픽셀)보다 낮게 둔다(지금 4픽셀).
- 지형의 맞닿은 면 숨기기는 칸 경계에 놓인 면을 1/16 단위로 나눠 이웃이 덮는 부분을 지운다. 칸 경계 면은 텍스처 픽셀 경계와 맞게 칠한다(1절 밀도).

### 장식 기둥

`Models/Decoration/Pillar/`, 모두 16 × 16 × 16. 몸통은 가운데 8 × 8(모서리를 깎은 팔각), 받침·머리는 끝 4픽셀 높이에서 14픽셀까지 넓어진다. 큐브 격자가 그룹을 보고 칸마다 하나를 고른다.

| 모델 | 모양 |
|---|---|
| `Pillar` | 받침 + 몸통 + 머리 (한 칸 그룹) |
| `PillarBase` | 받침 + 몸통 (그룹 맨 아래) |
| `PillarShaft` | 몸통만 (그룹 가운데) |
| `PillarTop` | 몸통 + 머리 (그룹 맨 위) |

## 7. MagicaVoxel로 모양 만들기 → 변환 → Blockbench에서 칠하기 (2026-11-19부터)

Blockbench에서 모양부터 만들기는 힘들어서, **모양은 MagicaVoxel로 만들고 변환해 Blockbench에서는 텍스처만 칠한다**(사용자 결정).

1. **MagicaVoxel로 모양**을 만든다. 원본 `.vox`는 프로젝트 루트 **`Voxel/`**에 둔다(하위 폴더는 `Assets/Models/`와 같게, 파일 이름 = 프리팹 이름. 예: `Voxel/Fixtures/BoomGate/BoomGate.vox`). MagicaVoxel 프로젝트 목록(`config/config.txt`의 `dir_model`)이 이 폴더다. Unity는 `Voxel/`을 가져오지 않는다(git에는 올라감).
2. **아트 세션이 변환**한다(`Voxel/_Tools/vox2bbmodel.py`): `Voxel/<경로>/<이름>.vox` → `Assets/Models/<경로>/<이름>.bbmodel`. 이미 있는 `.bbmodel`을 덮어쓰면 이전 파일을 `Voxel/_Backup/`에 백업하고 **칠을 새 모델로 옮긴다**(아래 '칠 유지').
3. **Blockbench에서 텍스처를 칠하고** 저장한다(1절대로 텍스처는 파일 안에).
4. **칠한 뒤 모양을 고치면** MagicaVoxel에서 고쳐 다시 변환한다. **칠은 유지**되고, 새로 드러난 면만 기본 색이 된다(그 면만 다시 칠함). Blockbench에서 바로 고쳐도 된다(그 뒤로 `.vox`와 모양이 달라짐. 큐브를 하나씩 붙였으면 아래 '큐브 합치기').

### MagicaVoxel 쪽 약속

- **복셀 모델은 단색으로** 만든다(사용자 결정, 2026-11-19): 부위마다 **대표 색 하나**만 쓰고 음영·무늬는 Blockbench에서 칠한다. 대표 색은 **gray = 16, color = 33, glass = 41, grayglass = 49**.
- **모양이 같은 모델은 `.vox` 하나**만 둔다(무늬만 다른 모델). 변환할 때 필요한 이름들로 만든다. 지금: `ConveyorBelt.vox` → `ConveyorBelt1~4`, `ConveyorBeltCurve.vox` → `ConveyorBeltCurve1~4`, `ConveyorBeltCurveL.vox` → `ConveyorBeltCurveL1~4`, `Point/Point.vox` → `PointActived`·`PointDisactived`.
- 팔레트는 `colormaze`(`Docs/아트/ColorMaze 팔레트.png`, MagicaVoxel `palette/colormaze.png`)를 쓴다. **칸 번호가 부위 태그**를 정한다.

| 색 번호 | 변환 뒤 태그 그룹 | 칠해지는 색 |
|---|---|---|
| 1~32 (회색 32단계), 57~255 | `gray` | 팔레트 색 그대로 |
| 33~40 (빨강 미리보기, 밝기 8단계) | `color` | 밝기 단계(가장 큰 채널)의 회색 |
| 41~48 (청록 미리보기, 밝기 8단계) | `glass` | 밝기 단계의 회색 |
| 49~56 (반투명 회색 8단계) | `grayglass` | 팔레트 회색 그대로 |

- `light` 태그는 팔레트 칸이 없다. 빛나는 부분은 변환 뒤 Blockbench에서 그 큐브를 `light` 그룹으로 옮긴다(필요해지면 칸을 정한다).
- **오브젝트 하나 = 부품 그룹 하나**(바깥 목록에서 붙인 이름 그대로, 없으면 `Object 1`…). 움직이는 부품은 오브젝트를 나누고 이름을 붙인다.
- 축: MagicaVoxel (X, Y, Z) → Blockbench (X, Z, −Y). MagicaVoxel **+Y(앞)가 Blockbench 북쪽**(Unity 앞), Z가 위다. 계단은 +Y로 오른다.
- 오브젝트 회전은 쓰지 않는다(변환이 읽지 않음). 재질(MATL)도 읽지 않는다.

### 변환이 하는 일

- 같은 부품·같은 태그의 칸을 큰 큐브로 합치고, 보이는 면마다 그 면에 닿은 칸의 색을 칠한 텍스처 영역을 준다(1픽셀 = 1칸, 다른 칸이 완전히 덮는 면은 끔). 텍스처는 한 장(폭은 64 이상 2의 거듭제곱)이다.
- **기준**: 모든 오브젝트를 합친 상자의 바닥면 가운데를 Blockbench 원점에 둔다(정수 픽셀이 되게 내림). 부품 그룹의 기준점(origin)은 그 오브젝트 상자의 바닥면 가운데(내림)라서, **움직이는 부품의 회전축은 Blockbench에서 고쳐 둔다**. 가져오기 기준점은 기본값(바닥면 가운데)을 쓴다.
- 2026-11-15 메인 세션의 Unity 변환 도구(`VoxToBBModel`)와 같은 계산이다(아트 세션이 Python으로 옮기고, 옛 변환 결과 6개와 큐브·그룹·면 픽셀이 같음을 확인).

### 칠 유지와 큐브 합치기 (`Voxel/_Tools/bbmerge.py`, 2026-11-19)

- **칠을 읽는 법**: 칸 하나의 면 하나 = 텍스처 1픽셀이므로, 칠을 **(칸 좌표, 면 방향) → 색**으로 읽어 새 큐브에 옮긴다. 면 uv·면 회전은 파일에 적힌 그대로 읽는다(가져오기 코드와 같은 방식).
- **다시 변환할 때 칠 유지**(`vox2bbmodel.py`가 자동으로 함): 새 모양을 옛 모델과 가장 많이 겹치는 위치에 맞춰(기준점이 밀려도 맞음) 옛 칠을 옮긴다. 옛 칠이 없는 면(새로 드러난 면)은 **기본 색**(gray 132 회색, 나머지 흰색)이다. 결과는 옛 모델 좌표 그대로다.
  - 이름 경로가 같은 그룹은 옛 그룹 설정(기준점·회전 등)을 그대로 쓴다. 옛 모델의 `light` 그룹 칸은 새 모델에서도 `light` 그룹으로 옮긴다.
  - 옮긴 칸은 칠이 따라가지 않는다(새 면 취급). Blockbench에서만 더한 큐브(회전한 큐브 등 `.vox`에 없는 것)는 빠진다.
- **큐브 합치기**: `python Voxel/_Tools/bbmerge.py <모델.bbmodel>` — 같은 그룹 바로 아래의 큐브를 큰 큐브로 합친다(칠 유지, 원래 파일은 `Voxel/_Backup/`에 백업). Blockbench에서 큐브를 하나씩 붙여 만든 모델(예: Creative Mode 플러그인)을 정리할 때 쓴다.
  - 합치는 큐브: 축이 맞고(회전 0) 좌표가 정수이고 inflate 0이고 숨기지 않은 큐브. 나머지(회전한 큐브, 반 칸 좌표)는 그대로 두고 그림만 새 텍스처로 옮긴다. 메시는 지원하지 않는다.
  - 그룹(이름·기준점·회전·순서)은 그대로다. 같은 부품 안에서 다른 칸이 완전히 덮는 면은 끈다(변환과 같은 규칙).
- 두 경우 모두 텍스처는 **한 장, 텍스처 크기 = UV 크기**(1픽셀 = 1칸)여야 하고, 새 텍스처 한 장으로 다시 짓는다(텍스처 레이어는 합친 그림 하나가 됨).
- 합친 결과는 **면마다 UV**(Box UV 끔)다. 텍스처가 없는 모델(모양만 만든 것)은 기본 색 텍스처를 새로 만든다. 그래서 Blockbench에서는 **모양만 만들고 텍스처는 만들지 않아도 된다**.
- **'모델 확인' 요청**(사용자 결정, 2026-11-19): 사용자가 Blockbench에서 모델을 만들거나 고친 뒤 '모델 확인'을 요청하면, 아트 세션이 `python Voxel/_Tools/bbmerge.py --changed`로 **처리 기록(`Voxel/_Backup/처리 기록.json`)과 다른 새·수정 `.bbmodel`만** 백업하고 합치기·텍스처 작업을 한 뒤, 모델마다 결과(큐브 수, 새 면 = 칠할 곳, 텍스처 새로 만듦 여부)와 규칙 확인(태그 그룹 밖 큐브, 합치지 못한 큐브, 1픽셀 = 1칸이 아닌 면, 겹친 칸)을 알린다. 요청 전에 Blockbench에서 그 모델 탭을 닫는다(열린 채 저장하면 작업을 덮어씀).
- 확인(2026-11-19): 지금 모델 26개 합치기 전후 보이는 면 칠 모두 같음, 1칸 큐브로 쪼갠 모델 3개(최대 4142개)를 다시 합쳐 원래 큐브 수·칠과 같음, 칠한 모델의 모양을 바꿔 다시 변환해 옛 면 칠 모두 유지·새 면만 기본 색·기준점과 `light` 그룹 유지.

### 지금 모델의 모양 원본 (2026-11-19)

- 그때 쓰던 `.bbmodel` 26개의 모양을 단색 `.vox` 16개로 `Voxel/`에 저장했다(`Voxel/_Tools/bbmodel2vox.py`: 축이 맞는 큐브를 칸으로 채우고, 부품 그룹 = 오브젝트, 부위 태그 = 대표 색). 다시 변환하면 같은 큐브 모양·부위가 나오는 것을 16개 모두 확인했다(텍스처는 단색). `BoomGateStick`은 반 칸 어긋난 좌표라 반 칸 옮겨 맞췄다.

### 이력: 옛 `.vox` 26개 자동 변환 (2026-11-15 끝남)

- 기존 `.vox` 26개는 변환 도구로 같은 폴더에 같은 이름의 `.bbmodel`을 만들었고(기준점 '원점 그대로'), 프리팹은 모두 새 모델로 바꿨다. `.vox` 파일·가져오기 코드·변환 도구는 `!!!!지울것`으로 옮겼다. 반투명 정도는 예전처럼 모델마다 하나(기본 0.5)다.

## 8. 가져오기 코드에 넘기는 메모 (정하는 것은 메인 세션)

- 텍스처는 가져올 때 부위별로 휘도 그림으로 바꿔 둔다(실행 중 계산 없음). Gray·Color·Light는 URP Lit, Glass·GrayGlass는 Lit Glass를 쓴다.
- Blockbench UV는 위쪽이 0, Unity UV는 아래쪽이 0이다(가져오기가 뒤집음).
- 칸 경계가 아닌 곳의 면 합치기, 메시 묶음, 콜라이더 생성 여부 등 세부는 메인 세션이 정한다.
