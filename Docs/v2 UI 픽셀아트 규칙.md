# Slime~ColorMaker~ UI 픽셀아트 규칙

최초 작성: 2026-11-18 (아트 세션, 'UI 픽셀아트 도구 채팅': Pixelorama로 UI 그림을 그린다)

- Pixelorama로 그리는 UI 그림과 `.pxo` 가져오기 코드가 함께 지키는 약속이다. UI 그림 규칙의 **단일 출처**이고, 결정의 근거와 이력은 `Docs/v2 결정 로그.md`에 있다.
- 모델 쪽 약속(`Docs/v2 블록벤치 모델링 규칙.md`)과 같은 생각을 따른다: **원본 파일을 그대로 `Assets`에 두고**, **이름(태그)으로 칠하는 방식을 정하고**, Unity는 **휘도만** 쓴다.
- 아트 세션은 이 규칙대로 `.pxo`를 만들어 `Assets`에 저장하는 데까지 한다. 가져오기 코드와 Unity 쪽 연결(UI 배치), git은 메인 세션이 맡는다.
- 규칙을 바꾸면 이 문서를 고치고 메인 세션에 알린다(가져오기 코드가 이 문서를 따른다).

---

## 1. 기본

- 도구는 **Pixelorama**(무료, 오픈소스, 2026-11-18 기준 v1.2.4)다.
- 그림은 **`.pxo` 그대로** `Assets`에 저장한다(PNG로 내보내지 않음). `.pxo`는 압축 파일이고 안에 레이어 이름·순서·표시 여부(`data.json`)와 프레임·레이어마다의 픽셀(RGBA)이 그대로 들어 있어서, 가져오기 코드가 레이어를 나눠 읽을 수 있다.
- 파일 하나가 **UI 요소 하나**다(버튼 하나, 창 하나, 아이콘 하나).
- **크기**: UI 그림 1픽셀 = 기준 화면(1920 × 1080) **3픽셀**이다. 화면 전체가 **640 × 360**픽셀 판이라고 생각하고 그린다. 720p 2배, 1080p 3배, 1440p 4배, 4K 6배로 흔한 해상도에서 모두 정수배가 된다.
- 아이콘은 **16 × 16**(블록 한 면과 같은 감각), 작은 아이콘은 **8 × 8**을 기본으로 한다. 그 밖의 그림(버튼, 창)은 필요한 크기로 그린다(정수 픽셀).

## 2. 레이어: 칠하는 방식 (태그)

블록벤치의 부위 태그 그룹과 같은 규칙이다.

- 레이어 이름(또는 레이어 그룹 이름)이 **태그**면 그 안의 픽셀이 그 방식이 된다. 레이어는 자기를 감싼 것 중 **가장 가까운 태그**를 따른다(레이어 자신의 이름이 먼저).
- 이름은 **대소문자를 구분하지 않는다**(`gray` = `Gray`). 같은 태그 레이어를 여러 개 둬도 된다(`Gray`, `gray` 등. 이름 뒤에 다른 말을 붙이지는 않는다).
- 어느 태그에도 속하지 않은 레이어는 `Gray`로 본다.
- Pixelorama에서는 **컬러로 그려도 된다.** Unity는 칠한 픽셀의 **휘도 Y**만 쓴다.
  - **휘도 Y** = 0.299 R + 0.587 G + 0.114 B (ITU-R BT.601, sRGB 0~1 값 그대로). 흰색 1, 검정 0. 블록벤치 규칙과 같다.

| 태그 | 색 | 쓰임 |
|---|---|---|
| **Gray** | 흑백: Y | UI의 대부분(테두리, 바탕, 그림자, 글자 아닌 무늬) |
| **Color** | Unity 색 × Y | 실행 중 색이 바뀌는 부분(지금 색 견본 등) |

- **Unity 색**: UI 요소(놓인 이미지)마다 하나. 메인 세션 코드가 정하거나 인스펙터에서 정한다.
- Color 레이어는 칠한 **색조는 쓰지 않고 휘도만** 쓴다. 흰색으로 칠하면 Unity 색 그대로, 어둡게 칠하면 그만큼 어둡게 칠해진다(음영을 넣을 수 있음).
- **방식은 나중에 더할 수 있다**(예: 반투명, 발광): 가져오기 코드의 방식 표에 한 줄을 더하고 이 표에 적는다.

## 3. 겹치기와 투명

- 가져오기는 **Pixelorama 화면처럼** 보이는 레이어를 순서대로 겹친다. 각 픽셀의 방식은 그 자리에서 **맨 위에 보이는 픽셀의 레이어**를 따른다.
- 그래서 픽셀의 투명도는 **완전 투명(0) 또는 완전 불투명(255)**만 쓴다(반투명 픽셀은 쓰지 않음). 레이어 불투명도(레이어 설정의 Opacity)도 100%로 둔다.
- **숨긴 레이어는 가져오지 않는다.** 밑그림·참고 그림은 숨긴 레이어로 두면 된다.
- 레이어 섞기 방식(Blend mode)은 기본(Normal)만 쓴다.

## 4. 프레임: 버튼 상태

- 버튼처럼 상태가 있는 요소는 **프레임 순서**로 상태를 그린다. 순서는 고정이다.

| 프레임 | 상태 |
|---|---|
| 1 | 기본 (Normal) |
| 2 | 올림 (Hover) |
| 3 | 누름 (Pressed) |
| 4 | 꺼짐 (Disabled) |

- 상태가 없는 요소(창, 아이콘)는 **1프레임**만 쓴다.
- 모든 프레임은 같은 크기다(Pixelorama가 그렇게 만든다).

## 5. 9-슬라이스 (늘어나는 테두리)

- 버튼·창처럼 크기가 바뀌는 그림은 **가장 작은 크기로 그리고**, 모서리가 깨지지 않게 늘이는 테두리 두께(9-슬라이스)를 정한다.
- Pixelorama에는 테두리를 표시하는 기능이 없으므로, 테두리 두께는 **Unity에서 파일마다** 정하고(가져오기 설정) 아래 표에 적는다.
- 테두리 안쪽(늘어나는 부분)은 늘어나도 어색하지 않게 **한 색이나 반복되는 무늬**로 칠한다.

| 파일 | 테두리 (왼·아래·오른·위, 그림 픽셀. Unity 가져오기 설정과 같은 순서) | 메모 |
|---|---|---|
| `Common/PanelRounded.pxo` | 9 · 9 · 9 · 9 | 64 × 64, 1프레임, Gray(테두리 179, 안 85), 둥근 모서리. 창 바탕과 버튼 공용(2026-11-20, 사용자 그림). 가장 작게 18 × 18 그림 픽셀(화면 54)까지 |
| `HUD/PanelValue.pxo` | 없음 (크기 그대로) | 51 × 15, 1프레임, Gray. 'R G B' 값 상자(칸 3개 15 × 11, 칸막이 1, 짙은 선 42·밝은 선 237·칸 안 어두운 회색). 2026-11-20 사용자가 칸막이를 1로 고치고 오른쪽 빈 2열을 잘라 51 × 15. 칸막이가 있어 늘이지 않는다(2026-11-20, 사용자 그림을 줄여 다시 그림) |

## 6. 글자

- **글자는 그림에 그리지 않는다.** UI 글자는 폰트(TextMesh Pro)로 쓴다. 나중에 다국어를 넣을 수 있게 하기 위해서다(결정 로그 6절).
- **폰트는 Galmuri**(갈무리, quiple, OFL 1.1, 2026-11-20 사용자 결정): `Assets/Fonts/Galmuri/`의 `Galmuri11.ttf`(12픽셀 격자, 버튼·창·시간), `Galmuri11-Bold.ttf`(제목), `Galmuri9.ttf`(10픽셀 격자, 값 상자 숫자), 라이선스 `ofl.md`. galmuri@2.40.3 npm 패키지의 외곽선 `.ttf`. 한글 전체, 라틴, 가나·한자가 들어 있다.
  - 폰트 1픽셀 = 그림 1픽셀(화면 3픽셀)이 되게 쓴다: Galmuri11은 화면 글자 크기 **36**, Galmuri9는 **30**(배율이 바뀌면 그 정수배). TextMeshPro 폰트 애셋은 SDF가 아닌 비트맵(Raster)·필터 없음(Point)으로 만든다(메인 세션).
- 그림 안의 기호(화살표, 아이콘)는 그려도 된다.

## 7. 폴더와 이름

- 저장 위치는 **`Assets/Sprites/UI/`**다. 하위 폴더는 화면별로 나눈다(예: `HUD/`, `Menu/`, `Pause/`). 여러 화면에서 같이 쓰는 것은 `Common/`.
- 파일 이름은 영어 PascalCase이고 **종류를 앞에 붙인다**: `Button…`, `Panel…`, `Icon…`, `Frame…`, `Bar…`. 예: `ButtonMain.pxo`, `PanelPause.pxo`, `IconTimer.pxo`.
- 버튼 상태는 파일 안 프레임이므로 이름에 상태를 붙이지 않는다.

## 8. 가져오기 코드에 넘기는 메모 (정하는 것은 메인 세션)

- `.pxo` 구조(Pixelorama v1.2.4 `src/Autoload/OpenSave.gd`에서 확인): ZIP 안에 `data.json`(프로젝트·레이어·프레임 정보), `mimetype`, `preview.png`(현재 프레임 축소 미리보기), `image_data/frames/<프레임 번호>/layer_<레이어 번호>`(번호는 1부터, 셀 그림의 원시 데이터. 보통 RGBA8, 프로젝트 이미지 형식은 `data.json`에 있음), 설정에 따라 `image_data/final_images/<프레임 번호>`(합친 그림)가 들어 있다. 레이어 이름·표시 여부·부모 그룹은 `data.json`에서 읽는다.
- 픽셀이 또렷하게 보이게 필터 없음(Point)·압축 없음으로 만들고, UI 그림 1픽셀이 기준 화면 3픽셀이 되게 한다(1절).
- **정한 것 (2026-11-18, 메인 세션, 사용자 동의)** — 코드는 `PxoImporter`·`PxoFile`(에디터), `PaintImage`·`PixelCanvasScaler`(UI), 셰이더 `UIPaint`. 자세한 흐름은 `Docs/v2 코드 흐름 설계.md` 8.1절.
  - **한 장 + 칠할 자리 표시**: 텍스처 한 장의 RGB는 휘도 Y, 알파는 방식(Gray 255, Color 254, 투명 0). UI에는 `PaintImage`를 쓴다(Color 자리에만 이미지 색을 곱함). 방식이 늘면 알파 값을 하나 더 쓴다.
  - **프레임 → 스프라이트**: 프레임을 가로로 이어 붙인 텍스처 한 장에서 프레임마다 스프라이트 하나(`Normal`·`Hover`·`Pressed`·`Disabled`, 4절 순서). 버튼은 스프라이트 바꾸기(Sprite Swap)로 상태를 보인다.
  - **9-슬라이스**: 파일마다 가져오기 설정(인스펙터)의 테두리(왼·아래·오른·위, 그림 픽셀). 5절 표에도 적는다.
  - **3배 크기**: 스프라이트 픽셀/유닛 100 ÷ 3(캔버스 기준 픽셀/유닛 100). Point 필터, 압축·밉맵 없음.
  - **정수배 유지**: UI 캔버스는 `PixelCanvasScaler`가 배율을 정한다. 화면에 640 × 360 판이 들어가는 가장 큰 정수 n으로 그림 1픽셀 = 화면 n픽셀(남는 화면은 여백).
  - 그림은 판을 요소 크기에 맞춰 그린다(투명 여백도 스프라이트에 들어감).
