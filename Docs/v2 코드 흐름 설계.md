## 1. 설계 기준

- **확장성**: 새 기물은 기반 클래스를 상속하거나 인터페이스를 구현하고 프리팹을 만드는 것으로 끝난다. 맵 매니저, 상호작용, 저장, UI는 기물의 종류를 모른다.
- **유지보수**: 규칙(무엇이 맞는가), 겉모습(어떻게 보이는가), 연결(누가 누구에게 알리는가)을 나눈다. 판정은 코어 규칙, 수치는 설정 애셋, 소리는 소리 연결 한 곳에서 바뀐다.
- **개발 편의**: 규칙은 EditMode 테스트로 확인하고, 맵은 Play 한 번으로 바로 시험하고, 맵 실수는 맵 검사가 먼저 잡고, 수치는 인스펙터(설정 애셋)에서 바꾼다.

규칙

1. 의존은 한 방향이다. 월드(기물·플레이어·맵)와 UI는 코어 규칙에 기대고, 코어 규칙은 아무것도 모른다. 월드는 UI 클래스를 모르고, 둘은 이벤트와 등록식 접근점으로만 만난다.
2. 규칙은 순수 C#이다(MonoBehaviour·씬 오브젝트를 쓰지 않음, UnityEngine 값 타입은 씀).
3. 기물 컴포넌트는 입력을 받아 규칙을 부르고, 상태를 바꾸고, 이벤트를 보내거나 겉모습에 알리는 일만 한다.
4. 겉모습은 따로 둔다(흔들림, 게이트 조리개, 방벽 조각, 색 칠하기). 아트를 바꿔도 로직은 그대로다.
5. 같은 씬 안은 인스펙터 참조, 씬을 넘는 연결(맵 씬 ↔ UIScene)은 EventBus나 등록식 접근점이다.
6. 전역 싱글톤은 늘리지 않는다. 맵 범위의 것은 맵 매니저(`MapManager.Current`)를 거친다.
7. 수치는 설정 애셋 한 곳에 두고 툴팁으로 설명한다.
8. 맵 설계 규칙 중 기계로 확인할 수 있는 것은 맵 검사가 잡는다.

## 3. 씬과 수명

### 3.1 씬 구성

- **부팅 씬**(`Boot`): `Bootstrap`이 전역 서비스를 정해진 순서로 깨우고 메인 메뉴 씬을 불러온다. `GameAudio`(BGM 클립·믹서 연결)도 여기 있다.
- **메인 메뉴 씬**(`MainMenu`): 메인 메뉴와 맵 선택 화면.
- **UIScene**: `UIManager`가 씬을 Single로 불러올 때마다 additive로 다시 얹는다(Unity의 씬 로드 알림을 들어 '열린 맵에서 바로 시작'도 같은 길). HUD, 일시정지 메뉴, 확인 창, 클리어 화면, 화면 페이드(맨 위 캔버스).
- **맵 씬**: 맵 기본 프리팹 `MapRoot` 하나 + 큐브 격자(`CubeGrid`) 하나 + 칸 기물.
  - `MapRoot` = 맵 매니저 + 소리 연결(`SoundEventPlayer`) + 맵 환경(`MapEnvironment`) + 빛 번짐 탐침 범위(`Probe Volume`, Global이라 맵 전체에 맞춰 스스로 옮겨짐) + 원점의 시작 지점(`StartPoint`, 방향만 씬에서 돌림) + 플레이어(`Player`, 카메라 포함). 설정 애셋 연결도 프리팹에 들어 있다.
  - 맵 환경이 만든 태양(`Sun (맵 환경)`, 숨김)이 씬 맨 위에 저장되어 있다(12.4절).
  - 큐브 격자는 만든 블록이 프리팹 덮어쓰기가 되지 않게 `MapRoot` 밖에 둔다.
  - 새 맵은 메뉴 `Slime~ColorMaker~/새 맵 만들기`로 만든다(12.3절).

### 3.2 전역 서비스

| 이름 | 맡는 일 |
|---|---|
| `GameManager` (`GameState`) | 전역 상태: Boot → MainMenu → Playing ⇄ Paused → Cleared, 종료 전 Quitting. 맵 매니저가 Playing, 클리어가 Cleared, 메인 메뉴가 MainMenu로 맞춘다. |
| `InputManager` | 키보드·마우스 입력과 게임플레이 입력 잠금(잠근 쪽이 하나라도 있으면 잠김, 지금은 화면 페이드가 잠금). 일시정지는 잠금이 아니라 `Time.timeScale = 0`. |
| `GameAudio`, `GameSettings`(`SettingsData`) | BGM과 믹서, 음량·마우스 감도(`settings.json`, v1과 같은 형식). 마우스 감도는 정하지 않았으면(0) 카메라 설정 애셋의 기본값(`GameSettings.MouseSensitivity`). |
| `ProgressStore` (`ProgressSave`) | 진행 저장(`colormaze_save.json`): 맵별 기록과 마지막 체크포인트 하나(13절). |
| `SceneFlow` | 씬 사이 이동: 맵 시작(처음부터·이어하기), '처음부터'(씬 재로드), 메인 메뉴로. 모두 검은 화면 뒤 시간을 되돌리고 씬을 불러온다. 받는 씬에 넘길 것(이어하기, 맵 선택 화면 바로 열기)은 요청으로 남기고 받는 쪽이 한 번 꺼낸다. |
| `UIManager` | UIScene 얹기(3.1). |

### 3.3 맵 매니저의 수명 (`MapManager`)

- 맵 씬마다 하나, 씬과 함께 생기고 사라진다. `MapManager.Current`가 맵 범위의 것을 찾는 유일한 길이다.
- 기물보다 먼저 깨어나도록 실행 순서를 앞에 둔다. 기물은 OnEnable에서 등록(맵 안 id → 기물), OnDisable에서 해제한다.
- 시작할 때: 상태를 Playing으로 맞추고, 맵 목록에서 자기 씬 이름으로 맵 id·버전을 찾고, 플레이어를 시작 지점으로 옮기고, 클리어 시간을 0으로 둔다. `SceneFlow`의 '이어하기' 요청이 있을 때만 저장된 체크포인트부터 시작한다.
- 클리어 시간은 게임 중에만 흐른다(일시정지·클리어 뒤 멈춤, '체크포인트로' 뒤에도 이어서 흐름).
- 체크포인트·되돌리기·낙사는 7.6절, 클리어는 7.5절.

### 3.4 열린 맵에서 바로 시작 (`DirectPlayLoader`)

- 에디터의 Play는 늘 부팅 씬부터 시작한다. 메뉴 `Slime~ColorMaker~/Play: 열린 맵에서 바로 시작`이 켜져 있으면(EditorPrefs) 부팅 뒤 열려 있던 씬을 경로로 바로 불러온다(Build Settings에 없어도 됨). 부팅 순서를 그대로 쓰므로 부팅 씬에만 있는 설정이 빠지지 않는다.
- 켜져 있을 때 Play를 누르면 고친 씬을 먼저 저장할지 묻는다(취소하면 Play도 취소).
- 첫 프레임에 씬을 바로 바꾸면 Hierarchy 창이 단언 오류를 내므로 한 틱 미뤄 불러온다.
- 바로 시작한 맵은 '이어하기'를 거치지 않았으므로 처음부터 시작한다(저장 기록은 지우지 않음).

## 4. 코어 규칙 (순수 C#)

### 4.1 색 (`ColorValue`, `ColorRules`, `CurrentColor`)

- `ColorValue`: R·G·B 정수 값(지금 색, 색 원천의 값, 요구 색, 채널 한도). 값 타입으로만 다룬다.
- `ColorRules`: 채널 한도 `Limit`(모든 채널 0~15, 고정), 값 검사(색 원천 값: 0이 아니고 세 채널이 모두 같지 않음, 요구 색: 모든 채널 1 이상·모두 같지 않음·한도 안), 비교, 값의 색(채널마다 값 ÷ 가장 큰 채널 값 = 그 비율에서 가장 밝은 색, (0,0,0)은 검정), 흑백(채널 평균).
- `CurrentColor`: (0,0,0)에서 시작. 흡수하면 더하고(채널마다 한도에서 자름), 문·목적지에 정확히 같은 값을 쓰면 (0,0,0)으로 비우고, 레이저 벽을 지나면 뺀다. 값이 바뀔 때만 `Changed`.

### 4.2 큐브 맵 (`CubeGridData`, `CubeGridRules`)

- 칸 규칙과 데이터는 11.1절.

### 4.3 컨베이어 (`ConveyorRules`)

- 모양(`ConveyorShape` 직진·우회전·좌회전)과 미는 규칙, 벨트 구역, 관성(`ConveyorInertia`), 벨트 자리(바닥 흔적 픽셀 자리)는 6.6절.

### 4.4 저장 데이터 (`MapSnapshot`, `ProgressSave`)

- `MapSnapshot`: 체크포인트에 저장하는 맵 상태 — 맵 id·버전, 플레이어 자리와 좌우 방향, 지금 색, 기물 상태 목록(`FixtureStateEntry` = 맵 안 id + 기물이 내보낸 JSON 문자열), 플레이 시간, 활성화된 체크포인트 id 목록. JsonUtility로 저장한다.
- `ProgressSave`: 형식 버전(시맨틱 버전), 저장 시각, 맵별 기록(`MapRecord`: 맵 id, 클리어 여부, 최고 시간), 지금 플레이 중인 맵의 체크포인트 하나. 체크포인트 꺼내기는 맵 버전이 다르면 버린다. 맵 시작 경고(`MapStartWarning`): 이 맵의 체크포인트가 있을 때만(시작하면 지움). 다른 맵의 체크포인트만 있으면 묻지 않고 바로 시작한다(이 맵의 체크포인트에 닿으면 덮어씀).

### 4.5 UI 접근점 (`BackStack`, `Confirm`, `ScreenFade`)

- 월드와 UI가 서로의 클래스를 모르도록 코어 규칙에 둔 등록식 접근점이다. UIScene의 화면이 켜질 때 등록하고 꺼질 때 뺀다. 등록된 것이 없으면(UI 씬 없음) 오류 로그를 남기고 할 일을 바로 한다.
- `BackStack`: 닫을 수 있는 화면(일시정지 메뉴, 확인 창, 맵 선택 화면)은 열 때 자기 '닫기'를 넣고 닫을 때 뺀다. ESC는 맨 위를 닫는다(7.7절).
- `Confirm`(`IConfirmDialog`): 진행이 사라지는 버튼과 맵 시작 경고의 확인 창.
- `ScreenFade`(`IScreenFader`): 검은 화면 페이드(체크포인트 복귀, 씬 이동).

## 5. 플레이어 (`MapRoot/Player`)

### 5.1 구성

- `Player` 오브젝트: `CharacterController`(피벗은 발밑), `ThirdPersonController`(이동), `TouchInteractionController`(닿음 상호작용), `PlayerColor`(지금 색), `PlayerColorView`(몸 색), `PlayerSquashView`(출렁임), `SlimeTrail`(바닥 흔적), `VoxPaint`(므엥 모델 칠하기). 몸 모델은 `Body`.
- `Player/Camera`: `ThirdPersonCamera`(가리는 것이 있으면 카메라를 당김).

### 5.2 이동 (`ThirdPersonController`, `PlayerMoveSettings`)

- WASD는 카메라가 보는 방향(카메라 yaw) 기준이고 캐릭터는 가는 방향으로 돈다. 점프는 없다(위 칸은 계단으로).
- 관성: 지면에서 관성 시간 동안 일정하게 빨라지고, 키를 떼면 그때 속도에서 관성 시간 동안 일정하게 느려진다. 공중에서는 수평 속도를 유지한다. 관성 시간은 밟은 바닥이 코팅이면 그 종류의 값(11.5절), 아니면 `PlayerMoveSettings.inertiaTime`.
- 컨베이어: 중심점이 벨트 구역 안이면 벨트 속도를 더하고, 벗어나면 벨트 관성으로 이어 간다(6.6절).
- 턱 넘기: 턱 넘기 높이 이하의 턱은 오르고, 그 높이 이하로 내려가는 곳에서는 떨어지지 않고 내려선다. 충돌은 한 번에 오르내리고 몸 모델과 카메라는 바뀐 높이를 짧게 따라간다(`VisualOffset`).
- 입력이 잠기면 이동을 받지 않고(중력은 계속), 일시정지 중에는 멈춘다. 옮기기(`Teleport`)는 속도를 초기화하고 카메라를 그 방향 뒤로 돌린다.

### 5.3 카메라 (`ThirdPersonCamera`, `ThirdPersonCameraSettings`, `CameraCollisionSettings`)

- 마우스로 캐릭터 둘레를 돈다(좌우 = 둘레, 위아래 = 높이 각도). 휠로 거리를 최소~최대 사이에서 바꾸고 실제 거리는 부드럽게 따라간다.
- 카메라 당기기: 바라보는 점에서 카메라 쪽으로 구를 쏴 지형·기물에 걸리면 그 앞까지 바로 당기고, 풀리면 부드럽게 돌아간다. 쏘기 전부터 구와 겹친 물체(거리 0, 턱을 오른 직후 낮아진 바라보는 점이 디딤판 상자 콜라이더와 겹침)는 가리는 것으로 보지 않는다. 방벽(반투명 판, `BarrierView`)도 너머가 보이므로 무시한다.
- 캐릭터의 자식이지만 매 프레임 월드 자리를 직접 정한다(캐릭터가 돌아도 따라 돌지 않음).

### 5.4 닿음 상호작용 (`TouchInteractionController`, `PlayerContext`)

- 캐릭터 몸 캡슐을 조금 키운 모양이 상호작용하는 기물(`IInteractable`: 색 원천, 문, 목적지)에 새로 닿은 순간 한 번 상호작용한다(떨어졌다 다시 닿으면 또 함). 트리거도 닿음으로 친다. 기물 레이어(`FixtureBase.LayerName`)만 찾는다.
- 상호작용 거리 안의 값 있는 기물(`IValueProvider`)의 (윗면 가운데, 값) 목록이 달라지면 '가까운 값들 바뀜'을 보낸다.
- 입력이 잠겨 있거나 일시정지 중이면 상호작용하지 않고 값도 숨긴다.
- 기물에는 `PlayerContext`(지금 색 등)만 넘긴다. 기물은 전역 플레이어를 찾지 않는다.

### 5.5 지금 색과 겉모습

- `PlayerColor`: `CurrentColor`를 들고, 바뀌면(그리고 시작할 때 한 번) '지금 색 바뀜'을 보낸다.
- `PlayerColorView`: 몸의 값 색·반투명 값 색 칸을 지금 색(가장 큰 채널을 최대 밝기로 한 비율)으로 칠한다(`VoxPaint`).
- `PlayerSquashView`(`PlayerSquashSettings`): 몸 메시의 꼭짓점만 바꾸는 출렁임(위아래 늘고 눌림 + 윗부분 흔들림, 바닥면은 평평). 출발·도착·착지 반응, 걷는 통통 튐, 가속도만큼 쏠림. 콜라이더·이동은 그대로다.
- `SlimeTrail`(`SlimeTrailSettings`, 셰이더 Trail): 캐릭터가 스스로 움직이는 동안 발바닥 아래 1/16유닛 픽셀을 지금 색으로 칠하고, 유지 시간 동안 흐려져 사라진다. 픽셀은 바로 밑의 실제 면 높이에 칠하고, 벨트 위 픽셀은 벨트를 따라 옮겨진다(6.6절). 코팅(렌더 큐 2998)보다 위에 그린다.

### 5.6 입력 (`InputManager`)

- 이동·시점·휠은 각 컴포넌트가 `InputManager`에서 읽는다. ESC는 일시정지 메뉴가 읽어 뒤로 가기 스택으로 보낸다(7.7절).

## 6. 기물

계열과 종류, 코드 이름의 단일 출처는 `Docs/v2 기물 분류.md`다.

### 6.1 공통 기반과 인터페이스

| 이름 | 맡는 일 |
|---|---|
| `FixtureBase` | 맵 안 id(맵 안에서 1부터, 에디터가 발급), 켜질 때 맵 매니저에 등록. 기물 레이어 이름. |
| `RequiredColorBase` | 요구 색을 가진 기물(문, 레이저 벽, 목적지). 요구 색의 렌더러와 복셀 모델을 요구 색으로 칠하고(에디터에서도 보임) 가까이 가면 요구 색을 보인다. |
| `IInteractable` | 닿으면 상호작용한다. |
| `IValueProvider` | 상호작용 거리 안에서 값 표시에 값을 보인다(레이저 벽은 상호작용하지 않지만 값을 보임). |
| `ISnapshotable` | 체크포인트에 상태를 문자열로 내보내고 되돌린다. |
| `ShakeView` | 겉모습: 거부 흔들림. 연출이 정해지면 이 컴포넌트만 바꾼다. |

### 6.2 색 원천 (`ColorSource`, 프리팹 `Orb`)

- 복셀 모델을 값의 색으로 칠한다(에디터에서도 보임). 닿으면 값을 지금 색에 더하고(채널마다 한도에서 자름) 흑백이 되며 '색 흡수'를 보낸다. 한 번만 흡수한다. 흡수 전에만 값을 보인다. 체크포인트에는 흡수 여부를 저장한다.

### 6.3 목적지 (`Goal`, 프리팹 `MeuengKing`)

- 맵당 하나. 몸의 값 색 부분이 요구 색이다. 부딪혀(막힌 상자 콜라이더) 지금 색이 요구 색과 정확히 같으면 맵 매니저에 클리어를 요청하고, 다르면 흔들리고 '색 거부'를 보낸다. 클리어한 뒤에는 상호작용하지 않는다.

### 6.4 문 계열 (`GateBase`)

- 요구 색과 길을 막는 콜라이더를 든다. 막음이 바뀌면 콜라이더만 켜고 끄고, 루트와 스크립트는 늘 켜 둔다. 겉모습은 겉모습 기반 컴포넌트에 알린다.
- **문**(`Door`, 겉모습 `OpenableView`) — 칸 기물 **게이트**(프리팹 `Gate`, `GateFaces`, `GateView`): 한 칸 큐브. 닿으면(열리는 면의 막는 판만 기물 레이어라 닿음을 받음) 지금 색이 요구 색과 정확히 같을 때 지금 색을 (0,0,0)으로 비우고 열기 시작한다(다시 닿아도 반응 없음, 값 숨김, 계속 열려 있음). 막는 판은 열림 연출이 끝나 다 열렸을 때(`OpenableView.FullyOpened`) 끈다. 체크포인트로 돌아가면 바로 열린 모양이 되고 막음도 바로 꺼진다. 다르면 흔들리고 '색 거부'. 닫혀 있는 동안만 요구 색을 보인다. 체크포인트에는 문마다 열림 여부를 저장한다.
  - 면 구성(`GateFaces`): 열리는 면(`CellFaces` 비트 묶음, 놓을 때마다 정하는 값, 여럿 가능)은 열리는 판(모델 `Gate`)과 기물 레이어 막는 판, 나머지 면은 안 열리는 판(모델 `GateWall`)과 지형 레이어 막는 판(늘 막음, 닿아도 아무 일 없음)을 켠다. 모서리 띠(`GateSide` 12)·꼭짓점(`GateEdge` 8)은 늘 켜져 있다. 모델은 바닥 면 기준이고 칸 가운데를 축으로 면마다 돌려 둔다. 문이 열 때 끄는 막는 콜라이더는 열리는 면 판의 것뿐이라 열리는 면만 구멍이 된다.
  - 열림(`GateView`): 열리는 판의 조각 넷(바람개비 모양 직사각형)이 각자 바깥 변 쪽(조각 무게중심이 치우친 축)으로 0.6초 동안 미끄러진다. 판 칸(14 × 14픽셀) 밖으로 나간 부분은 메시 꼭짓점을 칸 안으로 눌러 넣고 텍스처 좌표를 같은 비율로 맞춰 잘라 그린다(축에 나란한 복셀 사각형이라 겹침 계산으로 끝남). 다 열리면 판을 끄고 '다 열림'을 알린다.
  - 방벽 가장자리: 묶음의 바깥 테두리인 띠·모서리 조각은 겉모습 프리셋의 가장자리 투명도로 칠한다(Play 시작 때 `BarrierView`가 정해 `VoxPaint.SetEdge`로 표시). 묶음의 다른 판이 그 띠의 두 끝점을 모두 가지면(나란히 이어지거나 ㄱ자로 꺾임) 안쪽, 아니면 가장자리. 모서리는 맞닿은 띠 둘 중 하나라도 가장자리면 가장자리. 혼자 있는 방벽은 테두리 전체가 가장자리. 편집 화면은 판 전체가 투명도.
  - 방벽 조각: 판 두께 1픽셀. 복셀 모델 아래에 조각 9개(판 가운데 `BarrierMain` 14 × 14, 가장자리 `BarrierSide` 넷, 모서리 `BarrierCorner` 넷, 같은 모델을 판 축으로 돌려 씀)를 둔다. 같은 칸의 다른 면 방벽과 가장자리가 겹치면 한쪽만 그 가장자리·모서리를 켠다(Play 중, `BarrierView`): 위·아래 > 북·남 > 동·서 순으로 앞선 쪽이 남는다. 모서리 조각은 맞닿은 두 가장자리 중 하나라도 양보하면 끈다. 다른 방벽이 사라지거나 다시 생기면 다시 고른다. 막는 상자도 판 두께(1/16)에 맞춘다.
- **레이저 벽**(`LaserWall`) — 칸 기물 **방벽**(프리팹 `Barrier`, 겉모습 `BarrierView`): 칸의 한 면(옆·위·아래, `CellFaceMount`)을 덮는 반투명 판(지나갈 수 있는지와 상관없이 늘 보임). 요구 색은 빼는 색이다. 지금 색의 모든 채널이 빼는 색 이상이면 막지 않고, 다 지나 반대쪽으로 나가면 지금 색에서 빼고 '레이저 통과'를 보낸다(들어갔다 되돌아오면 빼지 않음). 모자라면 막는다. 지나감은 막는 상자와 같은 자리의 트리거(맨 위 오브젝트에 둠, 트리거 메시지가 콜라이더의 오브젝트에만 가기 때문)로 잰다. 플레이어가 묶음 안에 있는 동안은 막지 않던 것을 켜지 않는다. 저장할 상태는 없다(지금 색에서 다시 계산, 체크포인트로 돌아갈 때 지나감 추적만 비움).
  - 이어진 방벽 묶음(`BarrierGroup`): 판이 맞닿고(판 네 꼭짓점 중 둘 이상을 함께 가짐, 칸 꼭짓점을 두 배 정수 좌표로 비교) 빼는 색이 같은 방벽을 이어 따라간 전부. 나란한 판, 같은 칸·옆 칸과 ㄱ자로 만나는 판, 등을 맞댄 판이 이어지고, 색이 다른 방벽에서 끊긴다. 켜진 방벽을 모두 알고, 방벽이 켜지거나 꺼지면 필요할 때 다시 만든다. 묶음은 벽 하나다: 플레이어가 묶음의 트리거 중 처음 들어간 곳을 기억하고, 묶음의 모든 트리거에서 빠져나갈 때 마지막으로 나간 방벽 기준으로 들어온 쪽과 반대쪽이면(판의 가장 얇은 축 기준) 한 번만 뺀다. 가까운 값은 묶음에 하나만 보인다(7.1절).

### 6.5 출발점 계열 (`SpawnPointBase`)

- 플레이어는 이 오브젝트의 위치(발밑)에 서서 이 오브젝트가 보는 방향을 본다.
- **시작 지점**(`StartPoint`): `MapRoot`의 자식으로 원점(0,0,0)에 있다. 방향은 씬에서 돌린다.
- **체크포인트**(`Checkpoint`): 플레이어가 처음 닿으면(트리거) 활성화되고 맵 매니저에 스냅샷을 요청한다. 겉모습은 발판 둘 중 하나(비활성 / 활성 = 시작 지점과 같은 모양). 활성화 여부는 스냅샷의 체크포인트 목록에 든다.

### 6.6 이동 계열: 컨베이어 벨트 (`ConveyorBelt`, `ConveyorRules`, `ConveyorBeltSettings`)

- 프리팹 `ConveyorBelt` 하나에 무늬 모델 12장(직선 `ConveyorBelt1~4`, 우회전 `ConveyorBeltCurve1~4`, 좌회전 `ConveyorBeltCurveL1~4`)이 있고, `shape`에 맞는 넷만 1 → 2 → 3 → 4 차례로 켠다. 차례는 게임 시간으로 정해 씬의 모든 벨트가 같은 번호를 보이고 일시정지하면 멈춘다. 에디터에서 `shape`를 바꾸면 켜진 무늬를 맞춘다.
- 블록 자리(칸 하나)에 깔리고 윗면이 블록 윗면과 같다. 모델 기준 흐름(나가는 쪽)은 −Z, 놓을 때 Y축으로 90°씩 돌린다. 꺾임은 모델 기준 −X 쪽(우회전) 또는 +X 쪽(좌회전)에서 들어온다. 켜진 벨트는 칸으로 찾을 수 있게 등록한다.
- 미는 규칙(`ConveyorRules`, 바닥 평면 x·z, 칸 단위):
  - 직선은 흐르는 방향으로 똑바로, 꺾임은 안쪽 모서리를 중심으로 칸 전체를 같은 각도로 돌린다(돌림판). 직선 1칸을 지나는 동안 꺾임은 90° 돌아, 어느 반지름에서든 지나는 시간이 같다.
  - 벨트 구역(모델의 난간 복셀과 같음): 직선은 폭 16칸 중 가운데 14칸, 꺾임은 반지름 1/16 이상 15/16 미만의 띠. 난간은 밀지 않는다.
  - 캐릭터는 중심점이 든 칸의 벨트 구역 안에 있을 때 그 벨트가 민다(`TryPush`, 속도 = 이동 ÷ 시간). 마주 흐르는 두 직선 벨트는 경계를 넘어 밀지 않고, 경계에서는 벨트 방향으로 움직이지 못한다(직각으로만).
  - 관성(`ConveyorInertia`): 중심점이 벨트 구역을 벗어나는 순간 벨트가 밀던 속도로 그 방향을 따라 똑바로 가며 관성 시간 동안 일정하게 느려진다(거리 = 빠르기 × 시간 ÷ 2). 같은 직선 방향으로 미는 벨트에 올라서거나 멈추면 끝난다. 조작과 따로 더한다.
  - 바닥 흔적: 꺾임 칸은 진행 × 반지름을 16 × 16 벨트 자리로 나눠 픽셀 자리로 쓴다. 벨트 무늬가 한 칸 흐를 때(`TryGetStep`) 벨트 위 픽셀을 1/16씩 옮긴다(`TryAdvance`). 난간 위 픽셀은 움직이지 않고, 벨트 밖으로 나가면 아래가 바닥이면 멈추고 비었으면 없앤다.

### 6.7 새 기물을 더하는 방법

1. 계열 기반(`FixtureBase`·`RequiredColorBase`·`GateBase`·`SpawnPointBase`)을 상속하거나 필요한 인터페이스를 구현한다. 상태가 있으면 `ISnapshotable`.
   - **변형은 프리팹 하나**: 모양·방향·면·종류처럼 같은 기물의 변형은 프리팹을 나누지 않고, 한 프리팹이 변형의 모델을 모두 자식으로 갖고 값(예: `ConveyorBelt.shape`, `PillarView.Shape`, `CellFaceMount`)으로 고른다. 지금 변형의 모델만 켜고, 에디터에서 값을 바꾸면 바로 보이게 한다. 편집 붓은 놓을 때 그 값을 정한다(장식·지형도 같음).
2. 겉모습은 겉모습 기반(`OpenableView` 등)이나 따로 둔 컴포넌트로 만든다.
3. 복셀 모델을 `Assets/Models/Fixtures/…`에 두고 프리팹을 `Assets/Prefabs/Fixtures/…`에 만든다(콜라이더는 기물 레이어).
4. 소리가 필요하면 이벤트를 더하고(9절) 소리 연결 애셋에 클립을 잇는다.
5. 큐브 맵 편집 붓에 더하고(`CubeGridEditing.Brush`, `CubeGridConfig`의 프리팹 칸) 맵 검사 항목을 더한다.
6. `Docs/v2 기물 분류.md`에 적는다.

## 7. 흐름

### 7.1 값 보기

- 닿음 상호작용 컨트롤러가 상호작용 거리 안의 `IValueProvider` 목록을 '가까운 값들 바뀜'으로 보내고, UIScene의 가까운 값 표시가 기물 윗면 조금 위의 화면 자리에 'R G B' 상자를 하나씩 그린다(카메라 거리와 상관없이 같은 크기, 카메라 뒤는 숨김). 입력이 잠기면 목록이 비어 숨는다. 목록의 기물마다 콜라이더 전체의 경계 상자를 보내고(이어진 방벽 묶음은 값 하나에 판마다의 상자, 상자 자리는 판들 위에서 캐릭터와 가장 가까운 점의 세로줄 가장 높은 윗면: 옆면 벽은 윗가장자리를 따라 미끄러지고 바닥 판은 판 위, 거리는 가장 가까운 판까지), 표시가 매 프레임 캐릭터 몸 가운데(`TouchInteractionController.Current.Center`)에서 그 상자까지 거리를 재어 보이기 시작하는 거리(4)에서 제 크기 거리(2)까지 상자를 시작 크기(0)에서 1로 키우고 투명도 0에서 1로 올린다(CanvasGroup). 세 값은 `GameRulesConfig`.

### 7.2 흡수

- 색 원천에 닿음 → `ColorSource`가 `PlayerContext`의 지금 색에 값을 더함 → `CurrentColor.Changed` → `PlayerColor`가 '지금 색 바뀜' → 지금 색 표시·몸 색이 바뀜. 색 원천은 '색 흡수'(소리)를 보낸다.

### 7.3 문·목적지에 색 쓰기

- 게이트의 열리는 면·목적지에 닿음 → 지금 색이 요구 색과 정확히 같은가(`ColorRules`) → 같으면 문은 지금 색을 비우고 열림('문 열림'), 목적지는 클리어 요청. 다르면 '색 거부'와 흔들림(지금 색 그대로).

### 7.4 레이저 벽 지나기

- '지금 색 바뀜'을 받을 때마다 막을지 다시 본다. 지나갈 수 있으면 방벽 묶음 전체가 막지 않고(판은 그대로 보임), 트리거로 묶음의 반대쪽까지 지나면 지금 색에서 한 번 빼고 '레이저 통과'.

### 7.5 클리어

- 목적지가 요청 → 맵 매니저가 상태를 Cleared로, 진행 저장에 기록(클리어·최고 시간)하고 체크포인트를 지움 → '맵 클리어'(클리어 시간) → 클리어 화면이 시간·최고 시간('새 기록')과 버튼(다음 맵·다시 하기·메인 메뉴, 마지막 맵이면 '맵 선택')을 보인다. 시간을 멈추고 커서를 보인다.

### 7.6 체크포인트, 되돌리기, 낙사

- 체크포인트에 처음 닿음 → 맵 매니저가 스냅샷을 만든다(기물마다 `ISnapshotable` 상태 + 플레이어 자리·지금 색·시간·활성 체크포인트) → 진행 저장에 바로 쓴다 → '체크포인트 도착'.
- '체크포인트로'(일시정지 메뉴): 검은 화면 사이에 씬을 다시 불러오지 않고 기물마다 상태를 되돌리고(부분 초기화), 플레이어를 체크포인트 자리·방향에 세운다. 플레이 시간은 되돌리지 않는다. 체크포인트가 없으면 '처음부터'와 같다.
- '처음부터': 그 맵의 체크포인트 기록을 지우고 씬을 다시 불러온다.
- 낙사: 가장 낮은 블록의 바닥보다 낙사 깊이(`GameRulesConfig`)만큼 아래로 떨어지면 '체크포인트로'와 같다. 페이드 중에는 다시 부르지 않는다.

### 7.7 ESC와 일시정지

- 일시정지 메뉴(`PauseMenu`)가 ESC를 읽는다: 뒤로 가기 스택에 닫을 화면이 있으면 맨 위를 닫고, 비어 있고 게임 중일 때만 일시정지를 연다(`Time.timeScale = 0`, 스택에 '계속하기'). 화면 페이드 중에는 ESC를 받지 않는다.
- 버튼: 계속하기·처음부터·체크포인트로·설정·메인 메뉴. 진행이 사라지는 세 버튼은 확인 창을 거친다. '설정'은 설정 화면을 열고, ESC로 닫으면 일시정지로 돌아온다.

### 7.8 메뉴 흐름

- 부팅 → 메인 메뉴: Play는 맵 선택 화면으로 바로 간다. '이어하기'는 저장된 체크포인트가 있을 때만 보인다(그 맵이 목록에 없거나 버전이 다르면 기록을 버리고 숨김).
- 맵 선택 화면: 맵 목록 순서의 맵 버튼(해금 없음)과 고른 맵의 미리보기(썸네일, 이름, 클리어 표시, 최고 시간), '시작'(경고가 필요하면 확인 창)·'이어하기'. ESC는 메인 메뉴로.
- 클리어 화면의 '다음 맵'은 체크포인트 경고만 거치고 바로 간다. 마지막 맵이면 메인 메뉴로 가서 맵 선택 화면을 바로 연다.
- 메인 메뉴 배경 파노라마: 메인 메뉴 카메라의 `MenuPanorama`가 설정 애셋(`MenuPanoramaSettings`)의 큐브맵을 하늘(Skybox/Cubemap, 셰이더는 컴포넌트가 참조해 빌드에 들어감)로 그리고 제자리에서 옆으로 돈다(속도·위아래 각도·시야각). 그림이 없으면 단색 배경. 그림은 에디터 메뉴 'Slime~ColorMaker~/메뉴 배경 찍기'(`MenuPanoramaCapture`)가 열린 맵의 씬 뷰 카메라 자리(Play 중이면 게임 카메라 자리: 면 숨기기·방벽 모서리·발광 광원·캐릭터가 들어감, 오버레이 UI는 안 들어감)에서 맵 카메라 설정을 본뜬 임시 카메라로 큐브맵을 그려 2:1 PNG(`Assets/Textures/MenuPanorama.png`, 큐브맵으로 가져옴)로 저장하고 설정 애셋에 넣는다(찍은 씬·자리도 적음, 후처리는 빠짐).

### 8.1 UI 픽셀아트 (`PxoImporter`, `PxoFile`, `PaintImage`, `PixelCanvasScaler`)

- 약속은 `Docs/v2 UI 픽셀아트 규칙.md`. Pixelorama `.pxo`(ZIP: `data.json` + 셀마다 원시 RGBA8, 셀은 그린 범위만·`offset`)를 그대로 가져온다.
- `PxoImporter`: 보이는 픽셀 레이어(자신과 부모 그룹이 모두 보임)를 아래부터 겹쳐 맨 위 픽셀을 남긴다. 픽셀의 방식은 그 레이어(또는 감싼 그룹)의 이름 태그(Gray·Color·Tint, 대소문자 무시, 없으면 Gray). 텍스처 한 장(알파 = 방식: Gray 255·Color 254·Tint 253·투명 0. Gray·Color는 RGB = 휘도 Y, Tint는 R = HSV 명도 V·G = 채도 S, Point·압축 없음)에 프레임을 가로로 붙이고, 프레임마다 스프라이트 `Normal`·`Hover`·`Pressed`·`Disabled`(1프레임이면 Normal 하나). 픽셀/유닛 100 ÷ 3이라 기준 화면에서 그림 1픽셀 = 3픽셀. 가져오기 설정: 9-슬라이스 테두리(그림 픽셀).
- `PaintImage`(Image를 늘림): 재질이 UI Paint 셰이더(`Assets/Material/UIPaint.mat`, 붙이면 에디터가 넣음)라 Color 픽셀에는 이미지 색 RGB를 곱하고, Tint 픽셀은 V × (흰색 × (1 − S) + 이미지 색 × S)(섞기는 sRGB 값으로 계산: Linear 색 공간에서 바꿔 계산 후 되돌림), Gray는 그대로, 알파는 전체에 곱한다. 일반 Image에 넣으면 Color·Tint 자리가 제 색으로 안 보인다. 지금 색 견본(`Hud/CurrentColor/Swatch`, `HUD/PanelColor` 15 × 15 Color 그림: 테두리 검정에서 가운데 흰색으로 밝아지는 회색 고리라 지금 색 × 밝기)이 PaintImage이고 이미지 색 = 지금 색.
- `PixelCanvasScaler`(CanvasScaler 대신): 캔버스 배율 = n ÷ 3, n = 화면에 640 × 360 판이 들어가는 가장 큰 정수(최소 1). 그림 1픽셀이 늘 화면 n픽셀이라 고르게 보인다(1080p·720p·1440p·4K는 지금의 1920 × 1080 늘이기와 같음).
- 적용(2026-11-20): UIScene·MainMenu 캔버스가 `PixelCanvasScaler`. 공용 9-슬라이스 그림 `Sprites/UI/Common/PanelRounded`를 창 바탕(일시정지·클리어·확인 창 상자, 맵 목록·미리보기)과 버튼 전부(맵 목록 버튼 포함)에 붙였다. 전부 Gray 그림이라 보통 Image(Sliced, 색 흰색)로 쓰고, 버튼 상태는 밝기 틴트(기본 0.85·올림 1·누름 0.7·고름 = 기본·꺼짐 0.5 반투명; 4프레임 그림이 오면 스프라이트 바꾸기로). 맵 목록에서 고른 버튼은 `MapSelectItem`이 파란 틴트(0.75, 0.8, 1). 그림을 붙인 요소의 크기·위치는 3의 배수(가운데 기준이면 크기는 6의 배수)로 맞춰 그림 1픽셀이 화면 3픽셀에 맞는다.
- HUD 값 상자(2026-11-20): 지금 색·가까운 값의 'R G B' 상자 바탕이 `Sprites/UI/HUD/PanelValue`(51 × 15, 늘이지 않음, 화면 153 × 45). 숫자 R·G·B는 각 칸(화면 x 6·54·102, y 6, 45 × 33) 가운데. 지금 색 견본은 45 × 45, 상자는 그 옆 6. 가까운 값 상자는 기물을 따라 움직이므로 `NearbyValueLabel`이 상자 왼쪽 아래 모서리를 화면 정수 픽셀로 반올림한다(그림 1픽셀은 늘 화면 n픽셀이라 테두리 굵기가 흔들리지 않고, 움직임은 1픽셀씩).
- 폰트(2026-11-20): UI 글자는 Galmuri 비트맵 TMP 애셋(`Assets/Fonts/Galmuri/* Bitmap.asset`, RASTER_HINTED·Point 필터·동적 아틀라스 1024·여러 장·빌드 때 비우기, 셰이더 Mobile/Bitmap). 샘플 크기는 폰트 격자(Galmuri11·Bold 12, Galmuri9 10)이고 글자 크기는 그 3배의 정수배: 버튼·본문·시간·맵 이름 Galmuri11 36, 작은 글(최고 기록·상태·기록)과 값 상자 숫자 Galmuri9 30, 창 제목 Bold 72(줄 높이 96이라 제목 줄도 96), 메인 타이틀 Bold 108. TMP 기본 폰트도 Galmuri11(36). 동적 애셋은 화면에 나온 글자가 파일에 쌓이므로 커밋 전에 비운다.

## 11. 큐브 맵

### 11.1 칸 규칙 (`CubeGridRules`)

- 한 칸은 1×1×1, 칸 좌표는 정수 (x, y, z). 칸은 x·z가 좌표 ±0.5, y가 좌표 ~ 좌표 + 1인 상자라 칸 중심은 (x, y + 0.5, z), 칸 바닥 가운데는 (x, y, z)다. y = −1 칸 블록의 윗면이 높이 0. 높이 제한·천장 없음. 맵은 한 층 구조가 아니라 높이가 자유롭다.
- 한 칸에는 블록·계단·기둥·기물 중 하나만 둔다(기물 검사는 편집 도구와 맵 검사). 방벽만은 면이 다르면 한 칸에 여럿 둔다(방벽과 다른 기물은 같은 칸에 못 둠). 방벽 붓으로 방벽만 든 칸을 가리키면 놓을 면이 비었을 때 그 칸에 더 놓고(아니면 앞 칸), 지우개는 칸의 것을 모두 지운다.
- 계산: 칸 ↔ 월드, 놓기·지우기, 두 칸 사이 상자 범위, 가장 낮은 칸(낙사 높이), 격자 광선(광선이 처음 지나는 찬 칸과 들어간 면 — 편집 도구가 콜라이더 대신 씀), 기둥 그룹 모양, 코팅 픽셀·붓.

### 11.2 데이터 (`CubeGridData`, JsonUtility, 나중의 UGC 맵 파일도 같은 클래스)

- `blocks`: 블록 칸 목록(블록은 아직 한 종류).
- `stairs`(`CubeStair`): 칸 + 오르는 방향(Y축 90° 돌린 횟수, 0 = +z). 지형이라 맵 안 id·상태가 없다.
- `pillars`(`CubePillar`): 칸 + 머리·받침 설정. 칸 모양(`PillarShape` 몸통·받침·머리·전부)은 저장하지 않고 `PillarShapes`가 계산한다: 바로 위·아래 칸의 같은 설정 기둥이 한 그룹(동서남북은 안 봄), 그룹 맨 아래에 받침, 맨 위에 머리(설정이면), 나머지는 몸통.
- `coatings`(`CubeCoating`): 블록 칸 + 윗면 16 × 16 픽셀의 `CoatingKind`(없음·기름·얼음, 번호 z × 16 + x). 블록이 있을 때만 칠하고, 다 지우면 목록에서 빠지고, 블록과 함께 지워진다.

### 11.3 큐브 격자와 빌더 (`CubeGrid`, `CubeGridBuilder`, `CubeGridConfig`)

- 큐브 격자는 맵마다 하나, 원점에 두고 돌리거나 늘리지 않는다(맵 검사). 데이터를 든다.
- 빌더는 블록·계단·기둥 프리팹을 '만든 부분' 아래 종류별 묶음(블록, 계단, 기둥)의 칸 중심에 놓는다. 기둥은 프리팹 하나(`Pillar`, `PillarView`)가 모양 넷의 모델을 모두 갖고, 빌더가 칸마다 계산한 모양을 `PillarView.Shape`로 맞춘다(지금 모양의 모델만 켜짐, 꺼진 모델은 콜라이더도 꺼짐). 묶음은 한 단계여야 한다(면 숨기기가 묶음 아래 오브젝트를 칸 하나로 봄). '코팅' 오브젝트의 `SlipperyCoatingView`도 다시 그린다.
- 다시 지을 때는 지금 것의 자리·방향을 데이터와 비교해 남은 칸은 두고, 없어지거나 돌아간 칸은 지우고, 새 칸만 만든다. 기둥 모양이 바뀐 칸은 다시 만들지 않고 모양 값만 바꾼다. 에디터에서는 프리팹 연결을 지키고 Undo에 기록한다.
- 블록·계단 프리팹은 static이고 블록마다 콜라이더 하나다. 계단 충돌은 복셀 모델 모양이다.

### 11.4 면 숨기기 (`CubeFaceCuller`)

- Play를 시작할 때 지형(블록·계단)의 맞닿은 면에서 이웃이 덮는 부분을 그리지 않는다. 축에 맞춘 면을 (방향, 평면 위치: 칸 안 1/16 간격 17곳)마다 16 × 16 그림(칸마다 그 자리 면의 평면 → UV 대응식)으로 바꿔 덮인 칸을 지우고, 남은 칸을 같은 대응식끼리 큰 사각형으로 다시 합친다(새 꼭짓점의 UV는 대응식으로 계산해 텍스처가 그대로 이어진다). 같은 (모델, 방향, 이웃 모양) 조합은 메시를 한 번만 만든다. 오브젝트·콜라이더·데이터·씬은 그대로다.
- 방벽(`BarrierView`) 판도 함께 넣는다. 불투명 면은 불투명 이웃에만 지워지고(반투명 뒤에서 보여야 함), 반투명 면은 불투명·반투명 이웃 모두에 지워진다(모델 가져오기 규칙과 같음): 블록과 닿는 방벽 뒷면, 바닥·천장 블록과 닿는 위아래 면, 나란한 방벽의 맞닿은 가장자리 면, 등을 맞댄 방벽의 뒷면. 방벽 모양(켜진 띠·모서리)이 바뀌면(`BarrierView.ShapeChanged`) `CubeGrid`가 그 칸과 여섯 이웃 칸을 다시 맞춘다. 한 칸의 두 면에 붙은 방벽의 모서리 겹침은 면 숨기기로 못 고쳐 조각을 끄고 켠다(위). 덮는 면은 이웃 칸 모델의 칸 경계 면(칸 경계 면끼리)과, 같은 칸의 다른 모델이 같은 평면에서 반대쪽을 보는 면이다: 가장자리를 양보한 방벽 판의 끝면과 그것이 닿는 다른 방벽 안쪽 면이 서로 지워진다.

### 11.5 미끄러운 코팅 (`SlipperyCoatingView`, `SlipperyCoatingSettings`)

- `[ExecuteAlways]`. 칠한 픽셀마다 블록 윗면과 같은 평면에 윗면만 그린다(옆면 없음). 같은 줄의 같은 종류 픽셀은 한 면으로 합친다. 무늬 UV는 월드 좌표라 칸마다 그림 한 장이 반복된다.
- 면은 저장하지 않는 숨긴 오브젝트(종류마다 하나)라 씬에 메시가 남지 않는다. 켜질 때·데이터가 바뀔 때·Undo 때·설정과 재질감이 바뀔 때 다시 만든다.
- 재질(CoatingOil·CoatingIce)은 Lit Glass(깊이 당기기) 반투명, 렌더 큐 2998이라 바닥 흔적보다 먼저 그린다. 재질은 늘 저장하지 않는 사본에 재질감을 입혀 쓴다.
- 캐릭터는 `TryGetInertiaTime(중심점)`으로 그 아래 픽셀의 관성 시간을 묻고, 밟은 바닥의 관성 시간이 바뀌면 멈춤 빠르기를 그때 속도로 다시 정한다.

### 12.2 맵 검사 (`MapValidator`)

- 메뉴 `맵 검사`로 지금 맵을 검사해 콘솔에 알린다(항목을 누르면 그 오브젝트로 감). 맵 씬을 저장할 때는 맵 안 id만 자동으로 본다.
- 검사 항목: 맵 매니저 1개, 맵 목록에 이 씬이 있는가, 시작 지점(원점)·목적지 1개, 맵 안 id(겹침·빈 id), 기물 콜라이더가 기물 레이어인가(게이트의 안 열리는 판 막는 상자는 지형 레이어라 뺌), 색 원천 값·요구 색 규칙(레이저 벽의 빼는 색은 색 원천 값 규칙 + 한도 안), 큐브 격자 1개(원점, 돌리거나 늘리지 않음)·칸 바닥 가운데에 놓이지 않은 기물·한 칸에 둘 이상(면이 다른 방벽끼리는 됨, 같은 면 방벽 둘은 문제)·블록이나 계단과 같은 칸의 기물, 맵 환경(없거나 설정이 빔, 태양 말고 다른 방향광). 조명이 지난 것이면(구운 적이 없거나 구운 뒤 바뀜) 경고만 한다(문제 수에는 안 셈).
- 맵 안 id 고치기(`FixtureIdAssigner`, 메뉴 `맵 안 id 고치기`): 빈 id와 겹친 id(계층에서 뒤쪽)만 지금 가장 큰 id + 1부터 새로 준다. 놓거나 복제할 때 자동으로 주지 않는다(큐브 맵 편집으로 놓으면 고침).

### 12.3 새 맵 만들기 (`NewMapWindow`)

- 맵 id·화면 이름·씬 이름을 받아: 빈 씬에 `MapRoot`와 큐브 격자를 넣고, 시작 칸 아래 (0,−1,0)에 블록 하나를 깔고, `Scenes/Maps`에 저장해 맵 목록(맨 뒤, 버전 1)과 Build Settings에 넣은 뒤 큐브 맵 편집 창을 연다. 목적지는 직접 놓는다.

### 12.4 맵 환경 (`MapEnvironment`, `MapEnvironmentSettings`)

- `MapRoot`에 붙어 설정 애셋의 하늘·환경 조명·반사(하늘)·안개(씬의 RenderSettings)와 태양을 그 맵에 적용한다. 에디터에서도 돈다(씬을 열 때, 애셋을 고칠 때).
- 태양은 맵 씬에 한 번 만들어 저장해 두는 숨긴 방향광(`Sun (맵 환경)`, 씬 맨 위, 고칠 수 없음)이고 값은 열 때마다 애셋에서 넣는다. 그래서 맵마다 프리팹 덮어쓰기가 생기지 않는다(맵에 다른 방향광은 두지 않음). 씬을 여는 중에도 찾을 수 있게 모든 광원에서 이름으로 찾고, 없으면 만들어 씬을 바뀐 것으로 표시한다.
- 태양은 Mixed(Baked Indirect): 빛 번짐(세기는 설정의 `sunBounce`)만 조명 굽기로 탐침에 굽고, 직접 빛·그림자는 실시간이다. 씬에 저장해 두어야 굽기가 태양의 굽기 기록을 남긴다(저장하지 않는 광원이면 굽기 때마다 Unity assert가 뜸).

### 12.5 모델 가져오기 (`BBModelImporter`, `BBModelFile`, `VoxPaint`)

- Blockbench `.bbmodel`(JSON, 형식 5.0)을 프리팹 겉모습으로 가져온다. 약속(부품·부위 태그, 폴더, 축·기준점, 블록·계단)은 `Docs/v2 블록벤치 모델링 규칙.md`. JSON은 Newtonsoft(`com.unity.nuget.newtonsoft-json`)로 읽는다.
- 그룹: 태그가 아닌 이름은 부품(자식 오브젝트, 원점 = 그룹 기준점), 태그 그룹(Gray·Color·Glass·GrayGlass·Light, 대소문자 무시)은 그 안 큐브의 부위다(태그가 없으면 Gray). 좌표는 Blockbench (X, Y, Z) → Unity (X, Y, −Z), 1유닛 = 16픽셀. 그룹·큐브 회전은 꼭짓점에 굽는다.
- 부위마다 렌더러 하나(이름은 `VoxPaint`가 찾는 이름): Gray = 부품 오브젝트 자신, Color = `ValueColor`, Glass = `GlassValueColor`, GrayGlass = `Glass`, Light = `Light`. 큐브끼리 맞닿아 완전히 덮인 면은 버린다(불투명 면은 불투명 면만 덮음).
- 텍스처는 모두 휘도 Y(BT.601) 회색으로 바꿔 한 장(아틀라스, 점 필터)에 모은다. 재질은 Gray·Color·Light = URP Lit(Light는 발광 텍스처도 아틀라스), Glass·GrayGlass = LitGlass 반투명(뒷면 → 앞면 재질 둘, 깊이를 카메라 쪽으로 당겨 다른 면에 붙어도 깨지지 않음).
- 가져오기 설정(파일마다): 기준점(바닥면 가운데·바닥면 뒤쪽 가운데·윗면 가운데·Blockbench 원점 그대로), 상자 콜라이더(축에 맞는 큐브마다 자식 `Collider (n)`에 BoxCollider, 지금 계단만 켬).
- `VoxPaint`(맨 위 오브젝트): 칠할 색(Color·Glass·Light), 투명도(Glass·GrayGlass, 0 = 불투명 ~ 1 = 안 보임, 알파 = 1 − 투명도, 프리팹마다 하나), 발광 세기(Light)를 렌더러마다 `_BaseColor`·`_EmissionColor`로 준다(에디터에서도 바로 보임). 투명도·발광 세기·재질감은 겉모습 프리셋(`ModelLook`, 12.6절)을 고르면 프리셋 값을 쓴다. 실행 중 연출용으로 `Glowing`이 있다. Light가 있는 부품에는 가져오기 코드가 광원(`LightSource`, 포인트·실시간)을 만들고, `VoxPaint`가 색(칠하는 색)·세기(발광 세기 × 광원 세기 배율)·범위·그림자를 맞춘다(값은 겉모습 프리셋 또는 자기 값). 기물이 `Glowing`을 끄면 발광과 광원이 꺼진다(흡수한 색 원천). 모델을 칠하는 곳은 여기 하나다: 기물·캐릭터 코드는 `Color`만 바꾼다.

### 12.6 재질감 (`SurfaceFinish`, `SurfaceFinishMaterials`, `SurfaceFinishGUI`)

- `SurfaceFinish` 애셋(`Assets/Data/Finishes`, 메뉴 Create > Slime~ColorMaker~ > 재질감): 광택(Smoothness), 반사(Metallic), 빛 맺힘(`_SPECULARHIGHLIGHTS_OFF`), 주변 반사(`_ENVIRONMENTREFLECTIONS_OFF`). 같은 애셋을 여러 곳이 같이 쓰고, 고치면 쓰는 곳이 모두 바뀐다.
- 프리팹: `VoxPaint`가 부위(일반·값 색·반투명)마다 재질감을 든다. 에디터의 `SurfaceFinishMaterials`가 렌더러에 '원래 재질(.bbmodel 가져오기 재질, 프리팹 원본에서 찾음) + 재질감' 재질을 끼운다. 그 재질은 재질감 애셋의 하위 애셋('모델 파일 이름(확장자 포함)/재질 이름')이라 같은 모델·같은 재질감끼리 하나를 같이 쓴다(묶어 그리기 유지). 재질감 값이 바뀌면 하위 재질만 다시 맞춘다. 비우면 원래 재질. 인스펙터 변경 중에는 애셋을 만들 수 없어 한 틱 미뤄 처리한다.
- 코팅: `SlipperyCoatingSettings`의 종류마다 재질감을 고른다(11.5절).
- 겉모습 프리셋(`ModelLook`, `Assets/Data/Looks`): 투명도·가장자리 투명도(방벽 묶음 테두리만, 프리팹 설정 창에는 방벽에만 보임)·발광 세기·광원(범위·세기 배율·그림자)·부위(일반·값 색·반투명·발광)마다 재질감을 묶은 애셋. `VoxPaint`가 고르면 자기 값 대신 쓴다(비우면 자기 값, 칠하는 색은 넣지 않음). 프리셋의 재질감이 바뀌면 `SurfaceFinishMaterials`가 그 프리셋을 쓰는 프리팹 애셋들을 열어 재질을 다시 끼운다(바뀔 것이 있을 때만). 지금 프리팹은 프리팹마다 하나씩(이름 = 프리팹 이름).
- 고르는 곳(`ModelLookGUI`): 프리팹 맨 위 오브젝트(Project 창의 프리팹, 프리팹 편집 화면의 맨 위, 씬에 놓인 프리팹의 맨 위)의 인스펙터 머리 부분 '모델 겉모습' 칸 — 프리셋 한 칸(그 프리팹의 모든 모델, 새로 만들기), 고른 프리셋의 값(모델들에 실제로 있는 부위의 것만, 재질감은 `SurfaceFinishGUI` 한 줄: 애셋 칸·새로 만들기·펼쳐서 값 고치기), 같이 쓰는 프리팹 수, '모델마다' 펼침. 씬에서 골랐으면 프리팹 애셋을 고친다. 모델 오브젝트의 `VoxPaint` 인스펙터(`VoxPaintEditor`)도 프리셋과 그 값을 보이고 자기 값은 흐리게 접는다. 코팅 설정 인스펙터(`SlipperyCoatingSettingsEditor`)도 같은 재질감 한 줄을 쓴다.
- 프리팹 설정 창(`PrefabSettingsWindow`, 메뉴 Slime~ColorMaker~/프리팹 설정): 왼쪽에 `Prefabs/Fixtures`·`Decoration`·`CubeGrid`의 프리팹 목록(폴더별, 미리보기, 검색), 오른쪽에 고른 프리팹의 '기물 값'(맨 위 오브젝트 컴포넌트의 값, 쓰는 설정 애셋은 펼쳐서 그 값도 고침)과 '모델 겉모습'(위와 같은 칸) (발광 부위가 있으면 발광 세기·광원 값도). 놓을 때마다 정하는 값(`[PerPlacement]`: 색 원천 값·밝기, 요구 색, 컨베이어·기둥 모양, 방벽이 붙는 면, 맵 안 id)과 씬 안 연결 참조는 숨긴다. 고치면 바로 저장한다.

### 12.7 조명 굽기 (`MapLightBaker`, `MapLightBuildStep`)

- 태양·환경 조명의 빛 번짐을 맵마다 Adaptive Probe Volume(탐침)에 굽는다. 블록 모델에 라이트맵 UV가 없고 Play 때 블록 메시를 바꿔 끼우므로(11.4절) 라이트맵을 쓰지 않는다: static 렌더러(블록·계단·기둥, 빛 번짐에 참여)도 Receive GI = Light Probes. URP 애셋(PC·Mobile)의 Light Probe System = Adaptive Probe Volumes.
- 굽기 설정은 공용 `MapLighting.lighting`(Baked GI, Realtime GI 끔, Mixed = Baked Indirect, 자동 굽기 끔), 탐침 간격은 맵 환경 설정의 `probeSpacing`. 맵마다 굽기 묶음(`<씬 이름> Baking Set`, 한 씬)을 씬 옆 씬 이름 폴더에 만든다.
- **조명 지문**: 굽기 결과를 바꾸는 것(빛 번짐에 참여하는 static 렌더러의 자리·메시·재질, 구울 광원, 맵 환경 설정 애셋, 하늘 재질, 굽기 설정 애셋)의 해시. 굽기를 시작할 때 계산해 다 구우면 `LightingFingerprint.txt`에 남긴다(멈춘 굽기는 남기지 않음). 지금 지문과 다르거나, LightingData·탐침 데이터가 없으면 '지난 조명'이다.
- **저장할 때**: 맵 씬을 저장하면(활성 씬, Play 아님) 지난 조명일 때만 백그라운드에서 굽는다(`Lightmapping.BakeAsync`, 다음 에디터 틱에 시작). 굽는 중에 바꿔 저장하면 멈추고 처음부터 다시 굽는다(같은 것을 굽는 중이면 그대로). 저장 직전(`sceneSaving`)에 굽기 설정과 굽기 묶음을 맞춘다.
- **빌드 전**(`MapLightBuildStep`): 맵 목록에 있고 Build Settings에서 켜진 맵을 차례로 열어 지난 맵만 저장 → 굽기(`Lightmapping.Bake`, 기다림) → 저장하고, 끝나면 열려 있던 씬으로 돌아간다. 굽지 못한 맵이 있으면 빌드를 멈춘다. 저장하지 않은 씬이 있으면 먼저 저장할지 묻는다.
- 메뉴: `조명 굽기`(지금 맵, 백그라운드, 지문과 상관없이), `모든 맵 조명 굽기 (바뀐 맵만)`(빌드 전과 같은 일). 큐브 맵 편집 창의 `다시 만들기`도 다시 만든 뒤 지금 맵을 굽는다.
- 실행 중: 블록·기물·므엥 모두 탐침에서 빛 번짐을 받는다. 태양은 구운 기록이 Baked Indirect라 직접 빛·그림자만 실시간으로 더한다.

### 12.8 반사

- 커스텀 반사(평면 반사·SSR·실내 반사 탐침)는 없다(2026-11-15 제거, 결정 로그). 매끈한 면은 모두 Unity 기본 하늘 반사를 비춘다: 맵 환경 설정의 반사 방식(Skybox·Custom)·큐브맵·세기를 맵 환경이 씬의 RenderSettings에 넣고, 조명 굽기가 하늘 반사 그림(`ReflectionProbe-0.exr`)을 굽는다.
- 금속·미끄러운 느낌은 재질감의 광택·반사(빛 맺힘, 하늘 반사)와 모델 그림으로 낸다. 실내도 하늘을 비추므로 실내에서 밝게 떠 보이면 광택을 낮춘다.
