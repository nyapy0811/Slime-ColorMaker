## 1. 설계 기준

- **확장성**: 새 기물은 기반 클래스를 상속하거나 인터페이스를 구현하고 프리팹을 만드는 것으로 끝난다. 맵 매니저, 상호작용, 저장, UI는 기물의 종류를 모른다.
- **유지보수**: 규칙(무엇이 맞는가), 겉모습(어떻게 보이는가), 연결(누가 누구에게 알리는가)을 나눈다. 판정은 코어 규칙, 수치는 설정 애셋, 소리는 소리 연결 한 곳에서 바뀐다.
- **개발 편의**: 규칙은 EditMode 테스트로 확인하고, 맵은 Play 한 번으로 바로 시험하고, 맵 실수는 맵 검사가 먼저 잡고, 수치는 인스펙터(설정 애셋)에서 바꾼다.

규칙

1. 의존은 한 방향이다. 월드(기물·플레이어·맵)와 UI는 코어 규칙에 기대고, 코어 규칙은 아무것도 모른다. 월드는 UI 클래스를 모르고, 둘은 이벤트와 등록식 접근점으로만 만난다.
2. 규칙은 순수 C#이다(MonoBehaviour·씬 오브젝트를 쓰지 않음, UnityEngine 값 타입은 씀).
3. 기물 컴포넌트는 입력을 받아 규칙을 부르고, 상태를 바꾸고, 이벤트를 보내거나 겉모습에 알리는 일만 한다.
4. 겉모습은 따로 둔다(강조, 흔들림, 방벽 흐려짐, 차단기 막대, 색 칠하기). 아트를 바꿔도 로직은 그대로다.
5. 같은 씬 안은 인스펙터 참조, 씬을 넘는 연결(맵 씬 ↔ UIScene)은 EventBus나 등록식 접근점이다.
6. 전역 싱글톤은 늘리지 않는다. 맵 범위의 것은 맵 매니저(`MapManager.Current`)를 거친다.
7. 수치는 설정 애셋 한 곳에 두고 툴팁으로 설명한다.
8. 맵 설계 규칙 중 기계로 확인할 수 있는 것은 맵 검사가 잡는다.

## 3. 씬과 수명

### 3.1 씬 구성

- **부팅 씬**(`Boot`): `Bootstrap`이 전역 서비스를 정해진 순서로 깨우고 메인 메뉴 씬을 불러온다. `GameAudio`(BGM 클립·믹서 연결)도 여기 있다.
- **메인 메뉴 씬**(`MainMenu`): 메인 메뉴와 맵 선택 화면.
- **UIScene**: `UIManager`가 씬을 Single로 불러올 때마다 additive로 다시 얹는다(Unity의 씬 로드 알림을 들어 '열린 맵에서 바로 시작'도 같은 길). HUD, 일시정지 메뉴, 확인 창, 클리어 화면, 화면 페이드(맨 위 캔버스).
- **맵 씬**: 맵 기본 프리팹 `MapRoot` 하나 + 큐브 격자(`CubeGrid`) 하나 + 칸 기물.
  - `MapRoot` = 맵 매니저 + 소리 연결(`SoundEventPlayer`) + 맵 환경(`MapEnvironment`) + 원점의 시작 지점(`StartPoint`, 방향만 씬에서 돌림) + 플레이어(`Player`, 카메라 포함). 설정 애셋 연결도 프리팹에 들어 있다.
  - 큐브 격자는 만든 블록이 프리팹 덮어쓰기가 되지 않게 `MapRoot` 밖에 둔다.
  - 새 맵은 메뉴 `Slime~ColorMaker~/새 맵 만들기`로 만든다(12.3절).

### 3.2 전역 서비스

| 이름 | 맡는 일 |
|---|---|
| `GameManager` (`GameState`) | 전역 상태: Boot → MainMenu → Playing ⇄ Paused → Cleared, 종료 전 Quitting. 맵 매니저가 Playing, 클리어가 Cleared, 메인 메뉴가 MainMenu로 맞춘다. |
| `InputManager` | 키보드·마우스 입력과 게임플레이 입력 잠금(잠근 쪽이 하나라도 있으면 잠김, 지금은 화면 페이드가 잠금). 일시정지는 잠금이 아니라 `Time.timeScale = 0`. |
| `GameAudio`, `GameSettings`(`SettingsData`) | BGM과 믹서, 음량·마우스 감도(`settings.json`, v1과 같은 형식). |
| `ProgressStore` (`ProgressSave`) | 진행 저장(`colormaze_save.json`): 맵별 기록과 마지막 체크포인트 하나(13절). |
| `SceneFlow` | 씬 사이 이동: 맵 시작(처음부터·이어하기), '처음부터'(씬 재로드), 메인 메뉴로. 모두 검은 화면 뒤 시간을 되돌리고 씬을 불러온다. 받는 씬에 넘길 것(이어하기, 맵 선택 화면 바로 열기)은 요청으로 남기고 받는 쪽이 한 번 꺼낸다. |
| `UIManager` | UIScene 얹기(3.1). |

### 3.3 맵 매니저의 수명 (`MapManager`)

- 맵 씬마다 하나, 씬과 함께 생기고 사라진다. `MapManager.Current`가 맵 범위의 것을 찾는 유일한 길이다.
- 기물보다 먼저 깨어나도록 실행 순서를 앞에 둔다. 기물은 OnEnable에서 등록(맵 안 id → 기물), OnDisable에서 해제한다.
- 시작할 때: 상태를 Playing으로 맞추고, 맵 목록에서 자기 씬 이름으로 맵 id·버전을 찾고, 플레이어를 시작 지점으로 옮기고, 클리어 시간을 0으로 둔다. `SceneFlow`의 '이어하기' 요청이 있을 때만 저장된 체크포인트부터 시작한다.
- 클리어 시간은 게임 중에만 흐른다(일시정지·클리어 뒤 멈춤, '체크포인트로' 뒤에도 이어서 흐름).
- 체크포인트·되돌리기·낙사는 7.6절, 클리어는 7.5절.

### 3.4 열린 맵에서 바로 시작 (`DirectPlayLoader`)

- 에디터의 Play는 늘 부팅 씬부터 시작한다. 메뉴 `Slime~ColorMaker~/Play: 열린 맵에서 바로 시작`이 켜져 있으면(EditorPrefs) 부팅 뒤 열려 있던 씬을 경로로 바로 불러온다(Build Settings에 없어도 됨). 부팅 순서를 그대로 쓰므로 부팅 씬에만 있는 설정이 빠지지 않는다.
- 켜져 있을 때 Play를 누르면 고친 씬을 먼저 저장할지 묻는다(취소하면 Play도 취소).
- 첫 프레임에 씬을 바로 바꾸면 Hierarchy 창이 단언 오류를 내므로 한 틱 미뤄 불러온다.
- 바로 시작한 맵은 '이어하기'를 거치지 않았으므로 처음부터 시작한다(저장 기록은 지우지 않음).

## 4. 코어 규칙 (순수 C#)

### 4.1 색 (`ColorValue`, `ColorRules`, `CurrentColor`)

- `ColorValue`: R·G·B 정수 값(지금 색, 색 원천의 값, 요구 색, 채널 한도). 값 타입으로만 다룬다.
- `ColorRules`: 채널 한도 `Limit`(모든 채널 0~15, 고정), 값 검사(색 원천 값: 0이 아니고 세 채널이 모두 같지 않음, 요구 색: 모든 채널 1 이상·모두 같지 않음·한도 안), 비교, 값의 색(채널마다 값 ÷ 가장 큰 채널 값 = 그 비율에서 가장 밝은 색, (0,0,0)은 검정), 흑백(채널 평균).
- `CurrentColor`: (0,0,0)에서 시작. 흡수하면 더하고(채널마다 한도에서 자름), 문·목적지에 정확히 같은 값을 쓰면 (0,0,0)으로 비우고, 레이저 벽을 지나면 뺀다. 값이 바뀔 때만 `Changed`.

### 4.2 큐브 맵 (`CubeGridData`, `CubeGridRules`)

- 칸 규칙과 데이터는 11.1절.

### 4.3 컨베이어 (`ConveyorRules`)

- 모양(`ConveyorShape` 직진·우회전·좌회전)과 미는 규칙, 벨트 구역, 관성(`ConveyorInertia`), 벨트 자리(바닥 흔적 픽셀 자리)는 6.6절.

### 4.4 저장 데이터 (`MapSnapshot`, `ProgressSave`)

- `MapSnapshot`: 체크포인트에 저장하는 맵 상태 — 맵 id·버전, 플레이어 자리와 좌우 방향, 지금 색, 기물 상태 목록(`FixtureStateEntry` = 맵 안 id + 기물이 내보낸 JSON 문자열), 플레이 시간, 활성화된 체크포인트 id 목록. JsonUtility로 저장한다.
- `ProgressSave`: 형식 버전(시맨틱 버전), 저장 시각, 맵별 기록(`MapRecord`: 맵 id, 클리어 여부, 최고 시간), 지금 플레이 중인 맵의 체크포인트 하나. 체크포인트 꺼내기는 맵 버전이 다르면 버린다. 맵 시작 경고(`MapStartWarning`): 이 맵의 체크포인트가 있음(시작하면 지움) / 다른 맵의 체크포인트가 있음(이 맵의 체크포인트에 닿으면 덮어씀).

### 4.5 UI 접근점 (`BackStack`, `Confirm`, `ScreenFade`)

- 월드와 UI가 서로의 클래스를 모르도록 코어 규칙에 둔 등록식 접근점이다. UIScene의 화면이 켜질 때 등록하고 꺼질 때 뺀다. 등록된 것이 없으면(UI 씬 없음) 오류 로그를 남기고 할 일을 바로 한다.
- `BackStack`: 닫을 수 있는 화면(일시정지 메뉴, 확인 창, 맵 선택 화면)은 열 때 자기 '닫기'를 넣고 닫을 때 뺀다. ESC는 맨 위를 닫는다(7.7절).
- `Confirm`(`IConfirmDialog`): 진행이 사라지는 버튼과 맵 시작 경고의 확인 창.
- `ScreenFade`(`IScreenFader`): 검은 화면 페이드(체크포인트 복귀, 씬 이동).

## 5. 플레이어 (`MapRoot/Player`)

### 5.1 구성

- `Player` 오브젝트: `CharacterController`(피벗은 발밑), `ThirdPersonController`(이동), `TouchInteractionController`(닿음 상호작용), `PlayerColor`(지금 색), `PlayerColorView`(몸 색), `PlayerSquashView`(출렁임), `SlimeTrail`(바닥 흔적), `VoxPaint`(므엥 모델 칠하기). 몸 모델은 `Body`.
- `Player/Camera`: `ThirdPersonCamera`, `CameraOcclusionFader`(시선 구멍, 지금은 꺼 둠 — 카메라 당기기를 씀).

### 5.2 이동 (`ThirdPersonController`, `PlayerMoveSettings`)

- WASD는 카메라가 보는 방향(카메라 yaw) 기준이고 캐릭터는 가는 방향으로 돈다. 점프는 없다(위 칸은 계단으로).
- 관성: 지면에서 관성 시간 동안 일정하게 빨라지고, 키를 떼면 그때 속도에서 관성 시간 동안 일정하게 느려진다. 공중에서는 수평 속도를 유지한다. 관성 시간은 밟은 바닥이 코팅이면 그 종류의 값(11.5절), 아니면 `PlayerMoveSettings.inertiaTime`.
- 컨베이어: 중심점이 벨트 구역 안이면 벨트 속도를 더하고, 벗어나면 벨트 관성으로 이어 간다(6.6절).
- 턱 넘기: 턱 넘기 높이 이하의 턱은 오르고, 그 높이 이하로 내려가는 곳에서는 떨어지지 않고 내려선다. 충돌은 한 번에 오르내리고 몸 모델과 카메라는 바뀐 높이를 짧게 따라간다(`VisualOffset`).
- 입력이 잠기면 이동을 받지 않고(중력은 계속), 일시정지 중에는 멈춘다. 옮기기(`Teleport`)는 속도를 초기화하고 카메라를 그 방향 뒤로 돌린다.

### 5.3 카메라 (`ThirdPersonCamera`, `ThirdPersonCameraSettings`, `CameraCollisionSettings`)

- 마우스로 캐릭터 둘레를 돈다(좌우 = 둘레, 위아래 = 높이 각도). 휠로 거리를 최소~최대 사이에서 바꾸고 실제 거리는 부드럽게 따라간다.
- 카메라 당기기: 바라보는 점에서 카메라 쪽으로 구를 쏴 지형·기물에 걸리면 그 앞까지 바로 당기고, 풀리면 부드럽게 돌아간다.
- 캐릭터의 자식이지만 매 프레임 월드 자리를 직접 정한다(캐릭터가 돌아도 따라 돌지 않음).

### 5.4 닿음 상호작용 (`TouchInteractionController`, `PlayerContext`)

- 캐릭터 몸 캡슐을 조금 키운 모양이 상호작용하는 기물(`IInteractable`: 색 원천, 문, 목적지)에 새로 닿은 순간 한 번 상호작용한다(떨어졌다 다시 닿으면 또 함). 트리거도 닿음으로 친다. 기물 레이어(`FixtureBase.LayerName`)만 찾는다.
- 상호작용 거리 안의 값 있는 기물(`IValueProvider`)의 (윗면 가운데, 값) 목록이 달라지면 '가까운 값들 바뀜'을 보낸다.
- 입력이 잠겨 있거나 일시정지 중이면 상호작용하지 않고 값도 숨긴다.
- 기물에는 `PlayerContext`(지금 색 등)만 넘긴다. 기물은 전역 플레이어를 찾지 않는다.

### 5.5 지금 색과 겉모습

- `PlayerColor`: `CurrentColor`를 들고, 바뀌면(그리고 시작할 때 한 번) '지금 색 바뀜'을 보낸다.
- `PlayerColorView`: 몸의 값 색·반투명 값 색 칸을 지금 색(가장 큰 채널을 최대 밝기로 한 비율)으로 칠한다(`VoxPaint`).
- `PlayerSquashView`(`PlayerSquashSettings`): 몸 메시의 꼭짓점만 바꾸는 출렁임(위아래 늘고 눌림 + 윗부분 흔들림, 바닥면은 평평). 출발·도착·착지 반응, 걷는 통통 튐, 가속도만큼 쏠림. 콜라이더·이동은 그대로다.
- `SlimeTrail`(`SlimeTrailSettings`, 셰이더 Trail): 캐릭터가 스스로 움직이는 동안 발바닥 아래 1/16유닛 픽셀을 지금 색으로 칠하고, 유지 시간 동안 흐려져 사라진다. 픽셀은 바로 밑의 실제 면 높이에 칠하고, 벨트 위 픽셀은 벨트를 따라 옮겨진다(6.6절). 코팅(렌더 큐 2998)보다 위에 그린다.

### 5.6 입력 (`InputManager`)

- 이동·시점·휠은 각 컴포넌트가 `InputManager`에서 읽는다. ESC는 일시정지 메뉴가 읽어 뒤로 가기 스택으로 보낸다(7.7절).

## 6. 기물

계열과 종류, 코드 이름의 단일 출처는 `Docs/v2 기물 분류.md`다.

### 6.1 공통 기반과 인터페이스

| 이름 | 맡는 일 |
|---|---|
| `FixtureBase` | 맵 안 id(맵 안에서 1부터, 에디터가 발급), 켜질 때 맵 매니저에 등록. `IInteractable`이면 상호작용할 수 있는 동안 강조(`InteractHighlightView`)를 켠다. 기물 레이어 이름. |
| `RequiredColorBase` | 요구 색을 가진 기물(문, 레이저 벽, 목적지). 요구 색의 렌더러와 복셀 모델을 요구 색으로 칠하고(에디터에서도 보임) 가까이 가면 요구 색을 보인다. |
| `IInteractable` | 닿으면 상호작용한다. |
| `IValueProvider` | 상호작용 거리 안에서 값 표시에 값을 보인다(레이저 벽은 상호작용하지 않지만 값을 보임). |
| `ISnapshotable` | 체크포인트에 상태를 문자열로 내보내고 되돌린다. |
| `InteractHighlightView`, `ShakeView` | 겉모습: 강조(자체 발광을 숨 쉬듯), 거부 흔들림. 연출이 정해지면 이 컴포넌트만 바꾼다. |

### 6.2 색 원천 (`ColorSource`, 프리팹 `Orb`)

- 복셀 모델을 값의 색으로 칠한다(에디터에서도 보임). 닿으면 값을 지금 색에 더하고(채널마다 한도에서 자름) 흑백이 되며 강조를 끄고 '색 흡수'를 보낸다. 한 번만 흡수한다. 흡수 전에만 값을 보인다. 체크포인트에는 흡수 여부를 저장한다.

### 6.3 목적지 (`Goal`, 프리팹 `MeuengKing`)

- 맵당 하나. 몸의 값 색 부분이 요구 색이다. 부딪혀(막힌 상자 콜라이더) 지금 색이 요구 색과 정확히 같으면 맵 매니저에 클리어를 요청하고, 다르면 흔들리고 '색 거부'를 보낸다. 클리어한 뒤에는 상호작용하지 않는다.

### 6.4 문 계열 (`GateBase`)

- 요구 색과 길을 막는 콜라이더를 든다. 막음이 바뀌면 콜라이더만 켜고 끄고, 루트와 스크립트는 늘 켜 둔다. 겉모습은 겉모습 기반 컴포넌트에 알린다.
- **문**(`Door`, 겉모습 `OpenableView`) — 칸 기물 **방벽**(프리팹 `Barrier`, `BarrierView`): 칸의 한 면(옆·위·아래, `CellFaceMount`)을 덮는 반투명 판. 닿으면 지금 색이 요구 색과 정확히 같을 때 지금 색을 (0,0,0)으로 비우고 열린다(판이 흐려지며 사라짐, 계속 열려 있음). 다르면 '색 거부'. 닫혀 있는 동안만 요구 색을 보인다. 체크포인트에는 열림 여부를 저장한다.
- **레이저 벽**(`LaserWall`, 겉모습 `PassableView`) — 칸 기물 **차단기**(프리팹 `BoomGate`, `BoomGateView`): 요구 색은 빼는 색이다. 지금 색의 모든 채널이 빼는 색 이상이면 막지 않고(막대가 들림), 다 지나 반대쪽으로 나가면 지금 색에서 빼고 '레이저 통과'를 보낸다(들어갔다 되돌아오면 빼지 않음). 모자라면 막는다. 지나감은 막는 콜라이더와 같은 자리의 트리거로 잰다. 플레이어가 그 자리에 있는 동안은 막지 않던 것을 켜지 않는다. 저장할 상태는 없다(지금 색에서 다시 계산, 체크포인트로 돌아갈 때 지나감 추적만 비움).

### 6.5 출발점 계열 (`SpawnPointBase`)

- 플레이어는 이 오브젝트의 위치(발밑)에 서서 이 오브젝트가 보는 방향을 본다.
- **시작 지점**(`StartPoint`): `MapRoot`의 자식으로 원점(0,0,0)에 있다. 방향은 씬에서 돌린다.
- **체크포인트**(`Checkpoint`): 플레이어가 처음 닿으면(트리거) 활성화되고 맵 매니저에 스냅샷을 요청한다. 겉모습은 발판 둘 중 하나(비활성 / 활성 = 시작 지점과 같은 모양). 활성화 여부는 스냅샷의 체크포인트 목록에 든다.

### 6.6 이동 계열: 컨베이어 벨트 (`ConveyorBelt`, `ConveyorRules`, `ConveyorBeltSettings`)

- 프리팹 `ConveyorBelt` 하나에 무늬 모델 12장(직선 `ConveyorBelt1~4`, 우회전 `ConveyorBeltCurve1~4`, 좌회전 `ConveyorBeltCurveL1~4`)이 있고, `shape`에 맞는 넷만 1 → 2 → 3 → 4 차례로 켠다. 차례는 게임 시간으로 정해 씬의 모든 벨트가 같은 번호를 보이고 일시정지하면 멈춘다. 에디터에서 `shape`를 바꾸면 켜진 무늬를 맞춘다.
- 블록 자리(칸 하나)에 깔리고 윗면이 블록 윗면과 같다. 모델 기준 흐름(나가는 쪽)은 −Z, 놓을 때 Y축으로 90°씩 돌린다. 꺾임은 모델 기준 −X 쪽(우회전) 또는 +X 쪽(좌회전)에서 들어온다. 켜진 벨트는 칸으로 찾을 수 있게 등록한다.
- 미는 규칙(`ConveyorRules`, 바닥 평면 x·z, 칸 단위):
  - 직선은 흐르는 방향으로 똑바로, 꺾임은 안쪽 모서리를 중심으로 칸 전체를 같은 각도로 돌린다(돌림판). 직선 1칸을 지나는 동안 꺾임은 90° 돌아, 어느 반지름에서든 지나는 시간이 같다.
  - 벨트 구역(모델의 난간 복셀과 같음): 직선은 폭 16칸 중 가운데 14칸, 꺾임은 반지름 1/16 이상 15/16 미만의 띠. 난간은 밀지 않는다.
  - 캐릭터는 중심점이 든 칸의 벨트 구역 안에 있을 때 그 벨트가 민다(`TryPush`, 속도 = 이동 ÷ 시간). 마주 흐르는 두 직선 벨트는 경계를 넘어 밀지 않고, 경계에서는 벨트 방향으로 움직이지 못한다(직각으로만).
  - 관성(`ConveyorInertia`): 중심점이 벨트 구역을 벗어나는 순간 벨트가 밀던 속도로 그 방향을 따라 똑바로 가며 관성 시간 동안 일정하게 느려진다(거리 = 빠르기 × 시간 ÷ 2). 같은 직선 방향으로 미는 벨트에 올라서거나 멈추면 끝난다. 조작과 따로 더한다.
  - 바닥 흔적: 꺾임 칸은 진행 × 반지름을 16 × 16 벨트 자리로 나눠 픽셀 자리로 쓴다. 벨트 무늬가 한 칸 흐를 때(`TryGetStep`) 벨트 위 픽셀을 1/16씩 옮긴다(`TryAdvance`). 난간 위 픽셀은 움직이지 않고, 벨트 밖으로 나가면 아래가 바닥이면 멈추고 비었으면 없앤다.

### 6.7 새 기물을 더하는 방법

1. 계열 기반(`FixtureBase`·`RequiredColorBase`·`GateBase`·`SpawnPointBase`)을 상속하거나 필요한 인터페이스를 구현한다. 상태가 있으면 `ISnapshotable`.
2. 겉모습은 겉모습 기반(`OpenableView`·`PassableView` 등)이나 따로 둔 컴포넌트로 만든다.
3. 복셀 모델을 `Assets/Models/Fixtures/…`에 두고 프리팹을 `Assets/Prefabs/Fixtures/…`에 만든다(콜라이더는 기물 레이어).
4. 소리가 필요하면 이벤트를 더하고(9절) 소리 연결 애셋에 클립을 잇는다.
5. 큐브 맵 편집 붓에 더하고(`CubeGridEditing.Brush`, `CubeGridConfig`의 프리팹 칸) 맵 검사 항목을 더한다.
6. `Docs/v2 기물 분류.md`에 적는다.

## 7. 흐름

### 7.1 값 보기

- 닿음 상호작용 컨트롤러가 상호작용 거리 안의 `IValueProvider` 목록을 '가까운 값들 바뀜'으로 보내고, UIScene의 가까운 값 표시가 기물 윗면 조금 위의 화면 자리에 'R G B' 상자를 하나씩 그린다(거리와 상관없이 같은 크기, 카메라 뒤는 숨김). 입력이 잠기면 목록이 비어 숨는다.

### 7.2 흡수

- 색 원천에 닿음 → `ColorSource`가 `PlayerContext`의 지금 색에 값을 더함 → `CurrentColor.Changed` → `PlayerColor`가 '지금 색 바뀜' → 지금 색 표시·몸 색이 바뀜. 색 원천은 '색 흡수'(소리)를 보낸다.

### 7.3 문·목적지에 색 쓰기

- 방벽·목적지에 닿음 → 지금 색이 요구 색과 정확히 같은가(`ColorRules`) → 같으면 문은 지금 색을 비우고 열림('문 열림'), 목적지는 클리어 요청. 다르면 '색 거부'와 흔들림(지금 색 그대로).

### 7.4 레이저 벽 지나기

- '지금 색 바뀜'을 받을 때마다 막을지 다시 본다. 지나갈 수 있으면 막대가 들리고, 트리거로 반대쪽까지 지나면 지금 색에서 빼고 '레이저 통과'.

### 7.5 클리어

- 목적지가 요청 → 맵 매니저가 상태를 Cleared로, 진행 저장에 기록(클리어·최고 시간)하고 체크포인트를 지움 → '맵 클리어'(클리어 시간) → 클리어 화면이 시간·최고 시간('새 기록')과 버튼(다음 맵·다시 하기·메인 메뉴, 마지막 맵이면 '맵 선택')을 보인다. 시간을 멈추고 커서를 보인다.

### 7.6 체크포인트, 되돌리기, 낙사

- 체크포인트에 처음 닿음 → 맵 매니저가 스냅샷을 만든다(기물마다 `ISnapshotable` 상태 + 플레이어 자리·지금 색·시간·활성 체크포인트) → 진행 저장에 바로 쓴다 → '체크포인트 도착'.
- '체크포인트로'(일시정지 메뉴): 검은 화면 사이에 씬을 다시 불러오지 않고 기물마다 상태를 되돌리고(부분 초기화), 플레이어를 체크포인트 자리·방향에 세운다. 플레이 시간은 되돌리지 않는다. 체크포인트가 없으면 '처음부터'와 같다.
- '처음부터': 그 맵의 체크포인트 기록을 지우고 씬을 다시 불러온다.
- 낙사: 가장 낮은 블록의 바닥보다 낙사 깊이(`GameRulesConfig`)만큼 아래로 떨어지면 '체크포인트로'와 같다. 페이드 중에는 다시 부르지 않는다.

### 7.7 ESC와 일시정지

- 일시정지 메뉴(`PauseMenu`)가 ESC를 읽는다: 뒤로 가기 스택에 닫을 화면이 있으면 맨 위를 닫고, 비어 있고 게임 중일 때만 일시정지를 연다(`Time.timeScale = 0`, 스택에 '계속하기'). 화면 페이드 중에는 ESC를 받지 않는다.
- 버튼: 계속하기·처음부터·체크포인트로·메인 메뉴. 진행이 사라지는 세 버튼은 확인 창을 거친다.

### 7.8 메뉴 흐름

- 부팅 → 메인 메뉴: Play는 맵 선택 화면으로 바로 간다. '이어하기'는 저장된 체크포인트가 있을 때만 보인다(그 맵이 목록에 없거나 버전이 다르면 기록을 버리고 숨김).

## 11. 큐브 맵

### 11.1 칸 규칙 (`CubeGridRules`)

- 한 칸은 1×1×1, 칸 좌표는 정수 (x, y, z). 칸은 x·z가 좌표 ±0.5, y가 좌표 ~ 좌표 + 1인 상자라 칸 중심은 (x, y + 0.5, z), 칸 바닥 가운데는 (x, y, z)다. y = −1 칸 블록의 윗면이 높이 0. 높이 제한·천장 없음. 맵은 한 층 구조가 아니라 높이가 자유롭다.
- 한 칸에는 블록·계단·기둥·기물 중 하나만 둔다(기물 검사는 편집 도구와 맵 검사).
- 계산: 칸 ↔ 월드, 놓기·지우기, 두 칸 사이 상자 범위, 가장 낮은 칸(낙사 높이), 격자 광선(광선이 처음 지나는 찬 칸과 들어간 면 — 편집 도구가 콜라이더 대신 씀), 기둥 그룹 모양, 코팅 픽셀·붓.

### 11.2 데이터 (`CubeGridData`, JsonUtility, 나중의 UGC 맵 파일도 같은 클래스)

- `blocks`: 블록 칸 목록(블록은 아직 한 종류).
- `stairs`(`CubeStair`): 칸 + 오르는 방향(Y축 90° 돌린 횟수, 0 = +z). 지형이라 맵 안 id·상태가 없다.
- `pillars`(`CubePillar`): 칸 + 머리·받침 설정. 칸 모양(`PillarShape` 몸통·받침·머리·전부)은 저장하지 않고 `PillarShapes`가 계산한다: 바로 위·아래 칸의 같은 설정 기둥이 한 그룹(동서남북은 안 봄), 그룹 맨 아래에 받침, 맨 위에 머리(설정이면), 나머지는 몸통.
- `coatings`(`CubeCoating`): 블록 칸 + 윗면 16 × 16 픽셀의 `CoatingKind`(없음·기름·얼음, 번호 z × 16 + x). 블록이 있을 때만 칠하고, 다 지우면 목록에서 빠지고, 블록과 함께 지워진다.

### 11.3 큐브 격자와 빌더 (`CubeGrid`, `CubeGridBuilder`, `CubeGridConfig`)

- 큐브 격자는 맵마다 하나, 원점에 두고 돌리거나 늘리지 않는다(맵 검사). 데이터를 든다.
- 빌더는 블록·계단·기둥 프리팹을 '만든 부분' 아래 종류별 묶음(블록, 계단, 기둥 위아래·아래·중간·위)의 칸 중심에 놓는다. 묶음은 한 단계여야 한다(면 숨기기가 묶음 아래 오브젝트를 칸 하나로 봄). '코팅' 오브젝트의 `SlipperyCoatingView`도 다시 그린다.
- 다시 지을 때는 지금 것의 자리·방향을 데이터와 비교해 남은 칸은 두고, 없어지거나 돌아간 칸은 지우고, 새 칸만 만든다. 기둥 모양이 바뀐 칸은 다른 묶음으로 옮겨진다. 에디터에서는 프리팹 연결을 지키고 Undo에 기록한다.
- 블록·계단 프리팹은 static이고 블록마다 콜라이더 하나다. 계단 충돌은 복셀 모델 모양이다.

### 11.4 면 숨기기 (`CubeFaceCuller`)

- Play를 시작할 때 지형(블록·계단)의 맞닿은 면에서 이웃이 덮는 부분을 그리지 않는다. 칸 경계의 면을 방향마다 16 × 16 그림으로 바꿔 덮인 칸을 지우고 남은 칸을 큰 사각형으로 다시 합친다. 같은 (모델, 방향, 이웃 모양) 조합은 메시를 한 번만 만든다. 오브젝트·콜라이더·데이터·씬은 그대로다.

### 11.5 미끄러운 코팅 (`SlipperyCoatingView`, `SlipperyCoatingSettings`)

- `[ExecuteAlways]`. 칠한 픽셀마다 블록 맨 위 1/16 자리에 면을 그린다: 윗면, 가장자리 픽셀은 바깥 옆면 띠(옆 칸이 블록이면 안 그림). 같은 줄의 같은 종류 픽셀은 한 면으로 합친다. 무늬 UV는 월드 좌표라 칸마다 그림 한 장이 반복된다.
- 면은 저장하지 않는 숨긴 오브젝트(종류마다 하나)라 씬에 메시가 남지 않는다. 켜질 때·데이터가 바뀔 때·Undo 때·설정과 재질감이 바뀔 때 다시 만든다.
- 재질(CoatingOil·CoatingIce)은 Lit Glass(깊이 당기기) 반투명, 렌더 큐 2998이라 바닥 흔적보다 먼저 그린다. 종류에 재질감이 있으면 재질의 저장하지 않는 사본에 입힌다.
- 캐릭터는 `TryGetInertiaTime(중심점)`으로 그 아래 픽셀의 관성 시간을 묻고, 밟은 바닥의 관성 시간이 바뀌면 멈춤 빠르기를 그때 속도로 다시 정한다.

### 12.2 맵 검사 (`MapValidator`)

- 메뉴 `맵 검사`로 지금 맵을 검사해 콘솔에 알린다(항목을 누르면 그 오브젝트로 감). 맵 씬을 저장할 때는 맵 안 id만 자동으로 본다.
- 검사 항목: 맵 매니저 1개, 맵 목록에 이 씬이 있는가, 시작 지점(원점)·목적지 1개, 맵 안 id(겹침·빈 id), 기물 콜라이더가 기물 레이어인가, 색 원천 값·요구 색 규칙(레이저 벽의 빼는 색은 색 원천 값 규칙 + 한도 안), 큐브 격자 1개(원점, 돌리거나 늘리지 않음)·칸 바닥 가운데에 놓이지 않은 기물·한 칸에 둘 이상·블록이나 계단과 같은 칸의 기물, 맵 환경(없거나 설정이 빔, 씬에 저장된 방향광).
- 맵 안 id 고치기(`FixtureIdAssigner`, 메뉴 `맵 안 id 고치기`): 빈 id와 겹친 id(계층에서 뒤쪽)만 지금 가장 큰 id + 1부터 새로 준다. 놓거나 복제할 때 자동으로 주지 않는다(큐브 맵 편집으로 놓으면 고침).

### 12.3 새 맵 만들기 (`NewMapWindow`)

- 맵 id·화면 이름·씬 이름을 받아: 빈 씬에 `MapRoot`와 큐브 격자를 넣고, 시작 칸 아래 (0,−1,0)에 블록 하나를 깔고, `Scenes/Maps`에 저장해 맵 목록(맨 뒤, 버전 1)과 Build Settings에 넣은 뒤 큐브 맵 편집 창을 연다. 목적지는 직접 놓는다.

### 12.4 맵 환경 (`MapEnvironment`, `MapEnvironmentSettings`)

- `MapRoot`에 붙어 설정 애셋의 하늘·환경 조명·반사·안개(씬의 RenderSettings)와 태양을 그 맵에 적용한다. 에디터에서도 돈다(씬을 열 때, 애셋을 고칠 때). 태양은 씬에 저장하지 않는 숨긴 방향광이라 맵마다 프리팹 덮어쓰기가 생기지 않는다(맵에 다른 방향광은 두지 않음).

### 12.5 복셀 모델 가져오기 (`VoxImporter`, `VoxFile`, `VoxMesher`, `VoxPaint`)

- MagicaVoxel `.vox`(버전 200)를 프리팹 겉모습으로 가져온다. 약속(팔레트, 칠하는 색 칸, 폴더, 부품·축·기준점)은 `Docs/v2 복셀 모델링 규칙.md`.
- 오브젝트 하나가 자식 하나. 1유닛 = 16칸. 같은 방향·층·색의 면은 큰 사각형으로 합친다(greedy meshing). 팔레트는 256 × 1 텍스처, 면마다 자기 색 칸 UV.
- 값 색 칸(33~40)은 `ValueColor`, 반투명 값 색(41~48)은 `GlassValueColor`, 반투명 회색(49~56)은 `Glass` 렌더러로 떼어낸다. 값 색 렌더러의 칸은 밝기만 남긴 회색이라 `_BaseColor`와 곱해진다. 반투명 부분은 바깥 껍질만 만들고 뒷면 → 앞면 재질 둘로 그린다(셰이더 LitGlass: 깊이를 카메라 쪽으로 당겨 다른 면에 붙어도 깨지지 않음).
- `VoxPaint`(맨 위 오브젝트): 칠할 색과 반투명 정도를 렌더러마다 `_BaseColor`로 준다(에디터에서도 바로 보임). 모델을 칠하는 곳은 여기 하나다: 기물·캐릭터 코드는 `Color`만 바꾼다.

### 12.6 재질감 (`SurfaceFinish`, `SurfaceFinishMaterials`, `SurfaceFinishGUI`)

- `SurfaceFinish` 애셋(`Assets/Data/Finishes`, 메뉴 Create > Slime~ColorMaker~ > 재질감): 광택(Smoothness), 반사(Metallic), 빛 맺힘(`_SPECULARHIGHLIGHTS_OFF`), 주변 반사(`_ENVIRONMENTREFLECTIONS_OFF`). 같은 애셋을 여러 곳이 같이 쓰고, 고치면 쓰는 곳이 모두 바뀐다.
- 프리팹: `VoxPaint`가 부위(일반·값 색·반투명)마다 재질감을 든다. 에디터의 `SurfaceFinishMaterials`가 렌더러에 '원래 재질(.vox 가져오기 재질, 프리팹 원본에서 찾음) + 재질감' 재질을 끼운다. 그 재질은 재질감 애셋의 하위 애셋('모델 파일 이름/재질 이름')이라 같은 모델·같은 재질감끼리 하나를 같이 쓴다(묶어 그리기 유지). 재질감 값이 바뀌면 하위 재질만 다시 맞춘다. 비우면 원래 재질. 인스펙터 변경 중에는 애셋을 만들 수 없어 한 틱 미뤄 처리한다.
- 코팅: `SlipperyCoatingSettings`의 종류마다 재질감을 고른다(11.5절).
- 고르는 곳(`SurfaceFinishGUI`): 프리팹 맨 위 오브젝트(Project 창의 프리팹, 프리팹 편집 화면의 맨 위, 씬에 놓인 프리팹의 맨 위)의 인스펙터 머리 부분 '재질감' 칸 — 모델들에 실제로 있는 부위만 한 줄씩(애셋 칸, 새로 만들기, 펼쳐서 값 고치기), 고르면 그 프리팹의 모든 모델이 함께 바뀌고 씬에서 골랐으면 프리팹 애셋을 고친다(모델마다 다르면 '여러 값'). 코팅 설정 인스펙터(`SlipperyCoatingSettingsEditor`)도 같은 한 줄을 쓴다.
